# 镜头策略路由：只加载当前镜头真正需要的能力

这张卡不是新的全流程，而是段落开工前的一次轻量判断。目标是避免两种错误：所有段都强制做白模、故事板和调度图；或者完全不判断，遇到高风险动作才临时补救。

## 一、先判断镜头结构

### `standalone` 独立镜头

没有上一段空间承接要求，从高清人物、场景和产品母资产重新开镜。默认不需要白模交接。

### `editorial_sequence` 分镜剪辑型

允许利用反应镜头、景别变化、遮挡、硬切或插入特写衔接。上一段尾帧不作为下一段首帧；只维持剧情、人物身份、服装、道具归属和必要的屏幕方向。

### `continuous_take` 连续一镜型

只有在同场景、同摄影机关系、同一开放动作必须连续时，才触发白模交接。上一段生成尾帧只用于观察，不负责下一段画质和身份。

## 二、条件能力

| 触发条件 | 加载能力 | 不触发时 |
|---|---|---|
| 连续一镜＋上一段存在＋严格空间承接 | 白模交接图 | 不制作白模 |
| 多人物 | 人物身份—当前站位表 | 单人不制作 |
| 多人台词 | 身份—站位—台词绑定表 | 无台词不制作 |
| 过肩、前后景分层、三人复杂关系或四人以上同框 | 彩模导演视角代理图 `director_view_proxy` | 简单标准构图不制作 |
| 复杂调度 | 俯视人物/摄影机调度图 | 简单站定不制作 |
| 多镜头或复杂动作 | 黑白线稿故事板 | 单一简单动作不制作 |
| 穿衣、打斗、舞蹈等复杂物理动作 | 原片/动作参考视频；没有则拆动作 | 普通动作不加载 |
| 产品穿着或尺度敏感互动 | 真人比例与穿前/穿后状态图 | 只展示产品时按需 |
| 连续生成深度达到2或已经模糊漂移 | 回到高清母资产重锚定 | 不额外重锚 |
| 用户要求强控制、Blender建模或1:1/一比一复刻 | `modeling_strong_control`，加载 `knowledge/capabilities/modeling-strong-control.md` | 普通改编继续按最低必要资产 |

## 三、参考源职责

- 白模交接图：只控制人物站位、姿态、距离、遮挡和摄影机透视；不得作为首帧，不控制人物外观。
- 彩模导演视角代理图：在最终摄影机视角中，用固定颜色对应固定人物，只控制人物排序、画面大小、前中后景、姿态和遮挡；不得控制正式服装颜色、人物身份、产品和最终纹理。可由图片生成功能制作，不依赖网页导演台。
- 黑白线稿：只控制当前镜头构图、动作阶段和镜头方向；提交生成时只用当前干净单格，不用带编号、文字和箭头的整页故事板。
- 原片动作视频：只控制动作、重心、速度、节奏和允许的摄影机运动；不覆盖人物身份、服装、产品和场景。
- 高清人物、产品、场景资产：始终是身份、结构、材质和清晰度的权威来源。
- 生成视频尾帧：只作为观察证据；不得成为下一代身份、纹理或画质主锚。
- Blender 空间控制模型：同一 `.blend` 和 camera 是人物站位、姿态、接触、遮挡、镜头路径、切点与动作时序的权威。完整 animatic 与所有关键帧必须由它派生；canonical 资产仍控制人物、产品、材质、颜色和清晰度。
- 建模覆盖完整且逐时点审核通过时，`director_view_proxy` 关键帧替代 storyboard/mannequin grid；`keyframes_only` 不得冒充连续动作视频控制。

## 四、命令

复制 `templates/project/shot-strategy-input.json`，填写当前段事实：

```bash
node src/cli.js shot-strategy --input /绝对路径/shot-strategy-input.json
```

输出包含：推荐路线、触发能力、需要的现有资产类型、检查项、警告、明确不需要的能力及每类参考源职责。

## 五、边界

- 路由器不替代讲戏本、独立创意审核或成片审核。
- 路由器不自动生成资产，也不产生费用。
- `assetRequirements` 是当前段建议，正式下游仍需通过锁定 segment contract 和 asset manifest。
- 教程中“多次生成挑选”不进入默认策略；第一次生成应以完整前置消歧为目标。
