# 复刻视频四种控制方式路由

这是导演工作台“复刻视频”的产品与后台路由合同。它和“原创剧情”是两个一级业务入口；原创剧情不进入本路由。

## 前台显示四种方式

| 选项 | 用户看到的说明 | 后台职责 | 是否需要逆向提示词 | 生成时是否需要原视频 |
|---|---|---|---|---|
| 分镜图 | 用宫格图控制构图、镜头顺序和关键动作节点；更省输入成本 | 原片按自然剧情边界切成 ≤15 秒段；逐帧取证；按真实 Shot/动作阶段组成 12、15 或更多宫格；高清修复并执行已批准的元素替换 | 是 | 否；最终只绑定经审核的分镜控制图和其他必要母资产 |
| 深度视频 | 用深度和动作信息控制身体运动、遮挡和空间关系 | 生成/登记深度视频；仅迁移动作、重心、速度、遮挡、相对深度和允许的镜头运动 | 是 | 不绑定彩色原视频，但必须绑定深度视频；输入成本可能接近原视频 |
| 原视频 | 直接让官方原生能力在原视频上替换人物、场景或产品 | 上传原视频并编译明确的保留/替换指令；可与其他两种方式组合 | 否，前提是只选这一项 | 是 |
| KOC 复刻 | 只替换说话主角，保留原片 B-roll、整轨音频、字幕、身体、产品与剪辑 | 全量抽取 A-roll；按连续表演边界切成 ≤15 秒；只在脖子以上精确匿名整头；首帧由用户选择不做、每段做或指定片段做；准备完成后各段并行编译、绑资产和预审；通过结果按源时码回插原片 | 是，但只逆向当前 A-roll 的台词、动作、微表情和身份替换约束 | 只绑定匿名后的 A-roll 控制片，不把 B-roll 送生成 |

分镜图、深度视频、原视频允许自由组合。KOC 复刻必须单独选择，因为它自带 A-roll 清单、头部匿名、并行生成和回填审计合同。不要把“建模”“白模”“首尾帧”等后台高级能力继续扩张为前台常规控制方式；首帧仅作为 KOC 内部的用户可选资产策略。

## 组合路由

| 用户选择 | 逆向拆解 | 控制权分配 |
|---|---|---|
| 仅分镜图 | 必须 | 分镜图控制镜头顺序、构图和关键动作状态；人物/商品/场景母资产控制身份与材质 |
| 仅深度视频 | 必须 | 深度视频控制动作与空间；母资产控制脸、表情、服装、商品和场景身份 |
| 仅原视频 | 跳过 | 原视频只按官方原生替换合同执行，明确什么保留、什么替换 |
| 分镜图 + 深度视频 | 必须 | 分镜图负责离散镜头与关键状态，深度视频负责连续动作和遮挡；冲突时先停在编译审查，不自行择一 |
| 分镜图 + 原视频 | 必须 | 分镜图是镜头结构证据，原视频提供官方原生编辑上下文；新人物/商品母资产仍为身份权威 |
| 深度视频 + 原视频 | 必须 | 深度视频只管动作/空间，原视频只管明确允许保留的源事实；两者不得覆盖新资产身份 |
| 三者全选 | 必须 | 每个输入一项主职责；如果同一维度出现两个权威，提示词包必须阻断并回到职责分配 |
| 仅 KOC 复刻 | 必须 | 原片决定时码、台词、身体动作、构图和剪辑；匿名 A-roll 只去除旧头部身份；用户人物图决定新身份；首帧按用户选择绑定；B-roll 不生成；最终使用原片整轨音频回填 |

调用逻辑：

```text
requires_reverse = selected contains 分镜图 OR selected contains 深度视频
native_only = selected equals [原视频]
koc_only = selected equals [KOC 复刻]
```

`requires_reverse = true` 时调用 `../prompt-templates/09-reverse-storyboard-engineer.md`；`native_only = true` 时直接进入官方原生替换指令编译；`koc_only = true` 时调用项目 Skill `koc-remake-orchestrator`，不得套用整片原生替换或 B-roll 生成规则。

## 两个一级业务入口

1. **复刻视频**：先选择上述四种控制方式，再做源视频取证、替换规划、资产绑定、提示词编译、付费审批、分段生成、最终剪辑与 Gate 5 接受。
2. **原创剧情**：面向约 1–2 分钟小剧情，从需求访谈、概念提案、故事结构和脚本开始；不伪造源视频权威，但与复刻共用资产账本、生成段、提示词编译、审计、付费边界、最终剪辑和 Gate 5。

## 硬边界

- 分镜图和深度视频都不能负责新人物身份或新商品结构、材质与卖点。
- 深度视频不能被当作表情、人脸或服装纹理参考。
- 宫格数由真实 Shot 和关键动作阶段决定，12/15 格是常见版式，不是硬指标。
- 段长上限来自当前模型/操作配置；默认按 ≤15 秒规划，不把 15 秒当机械剧情切点。
- 任何组合都不绕过提示词/资产审计、单次付费授权、最终剪辑和 Gate 5 用户接受。
- KOC 首帧策略必须由用户明确选择：`none / all_segments / selected_segments`。不得把“所有片段都做首帧”继续作为默认值。
- KOC 并行化只在准备屏障通过后启动：A-roll 全量账本、≤15 秒连续边界、人物身份图、全部匿名控制片、首帧选择均已锁定。每段可独立编译、绑资产和预审；付费提交仍逐节点审核授权；最终回插和覆盖审计串行收口。
- 该文件是产品与路由合同；四路选择、KOC 首帧策略、KOC 执行合同与可恢复并行计划已落入当前 Harness。真实媒体抽取、平台生成和回填仍必须以各项目的锁定资产、节点读回和 Gate 5 证据为准。
