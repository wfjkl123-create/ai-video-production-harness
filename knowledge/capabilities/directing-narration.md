# 讲戏机制（每镜必用）

> 触发条件：所有项目、所有镜头。这不是可选分支，是提示词编译前的必经步骤。

## 什么是讲戏

在写任何提示词之前，先用导演视角把这一镜"讲"一遍。不是写给模型看的，是写给自己看的——把创作意图钉死，后面每一步都不用重新猜。

## 讲戏纪律

1. 只写镜头拍得到的具体物理动作（"揉太阳穴"而不是"表现疲惫"）
2. 光写到具体光源和方位（"左前方 45° 窗光"而不是"柔和光线"）
3. 情绪靠动作和环境托，不直说（"她嘴角牵起一个疲惫的半笑"而不是"她很难过"）
4. 提示词可以短，但戏要讲到位
5. 电影感是讲出来的，不是堆形容词堆出来的

## 讲戏模板

每镜编译前，先填写：

```
【讲戏】Segment XX / Shot XX
画面里有什么：[具体物件、人物、空间关系]
人物做了什么：[穷尽到身体部位的具体动作序列]
谁说什么：[台词/旁白/无]
镜头怎么走：[机位、运动方向、速度、起止景别]
光从哪儿打：[主光方向、色温、质感]
要让人感觉到什么：[一个情绪词 + 为什么]
这一镜的"戏眼"：[整段最核心的一个瞬间]
表演模式：[none / basic / emotion_dlc]
```

当镜头存在情绪转折、对白反应、潜台词、近景表演或复杂矛盾情绪时，加载 `dlc/emotion-performance.md`，设置 `performanceMode: emotion_dlc` 并填写 `performancePlan`。新建或重写的复杂表演使用 `actingControlVersion: 2`：记录保护策略的裂缝、对白触发词、禁止提前反应，以及面部主导/爆发时的进入—峰值—退出。普通动作镜头用 `basic`，没有人物表演的镜头用 `none`。旧讲戏本缺少该字段时仍可读取，但新讲戏本必须明确选择。

当镜头包含多人关系、首帧必须立即交代人物关系、地标接触、精确站位或受控切镜时，另填 `spatialContract`。它不是提示词模板，而是可复核的空间事实：首帧策略、必见主体、机位侧、每个主体的画面位置/世界位置/景深层/身体朝向/视线目标/运动方向/地标锚点，以及必要的切镜原因。`relationship-eyeline-v1` 命中时，讲戏本 `revision >= 2` 必须带此合同；`revision = 1` 的已锁定历史档案仍可读取。最终只把其中可见约束送入提示词正文，审计细节留在讲戏档案。

## 讲戏 → 提示词的转化

讲戏稿是中间产物，不直接喂模型。转化规则：

- 讲戏里的"画面里有什么" → 参考图绑定（不在提示词里重复描述外观）
- 讲戏里的"人物做了什么" → 提示词的画面内容（只写动）
- 讲戏里的"镜头怎么走" → 提示词的运镜部分
- 讲戏里的"光从哪儿打" → 提示词的氛围/画质部分
- 讲戏里的"要让人感觉到什么" → 先写清它由什么事件触发、人物为什么做出选择，再压缩成提示词中的可见情绪因果；禁止只写抽象情绪标签，也禁止把情绪动机全部留在讲戏里
- 讲戏里的 `performancePlan` → 用 `performance-capsule` 生成两份产物：完整 `emotion-performance-v1` 胶囊只作审计留档；模型正文只机械绑定紧凑的 `performance-continuity-v1` 时间守卫、结束状态与连续保留。每个镜头的故事作用、触发事件、动作动机和可见表演仍由 canonical Prompt Skill 写进自然导演语言；FACS/AU、内部目标、潜台词和策略标签不得进入模型正文

## 与 harness 衔接

讲戏稿作为 `shot_narration` 录入 project-state，是 compile-seedance 的上游输入。
没有讲戏稿的镜头，compile-seedance 应拒绝编译。
