# DLC：情绪表演与真人感

> 类型：镜头级按需能力，不是所有项目默认加载。
> 目标：把“她很难过、他很生气”改写成可见、连续、可检查的表演指令，同时约束人物身份、手脸风险和镜头节奏。

## 1. 什么时候自动启用

当前镜头命中任一条件时，将 `performanceMode` 设为 `emotion_dlc`：

- 剧情存在明确情绪转折、关系变化、潜台词或决定；
- 中近景、近景、特写里，人物反应是镜头的主要内容；
- 有台词、沉默回应、说一套做一套或“想做但停住”的文戏；
- 用户明确要求真人感、微表情、哭戏、怒戏、矛盾情绪或表演强度；
- 多角色镜头需要明确主动者、接收者和延迟反应。

以下情况设为 `none` 或 `basic`，不加载本文件：纯产品特写、空场景、纯运镜、纯动作证明、人物只承担简单拿放动作、现有讲戏字段已经足够的普通镜头。

这是镜头级路由，不是新审核门。锁定剧本和 Shotlist 之后，AI 可自动为命中的镜头启用；它不改变故事方向、分段或资产范围。

## 2. 两份来源怎样使用

设计来源：

- `100种情绪表达_分类版.md`：吸收十类情绪家族、五轨先后、主导轨轮换、复合情绪“主色 + 一个破绽”和特殊状态先锁身体支点。
- `AI视频情绪表演提示词生成系统_公开版_v2.md`：吸收事件驱动、六条表演轨道、四档强度、连续状态、多人反应链、呼吸声音、结尾双锁和失败修正。

不直接复制 100 条或 40 条成品句，不把固定台词“走开啊”、固定 15 秒节奏或整套长模板塞进每个提示词。来源文档只用于设计本 DLC；运行时只加载本文件和当前镜头的结构化计划。

## 3. 表演导演的判断顺序

1. **戏的作用**：这一镜要让关系、信息或人物决定发生什么变化？
2. **人物目标**：角色此刻想让对方相信、停止、留下、离开或看见什么？
3. **潜台词**：嘴上说的和身体真正泄露的是否矛盾？
4. **阻碍与策略**：什么阻止人物达成目标？他先用什么可见策略推进，策略失效后怎样换法？
5. **可见触发**：一句台词、手机震动、门响、物件接触、视线相撞或光线变化，什么让表演开始？
6. **表演质感**：克制写实、生活化写实、有控制的强戏剧表演或风格化冷面表演，只选一种。
7. **强度**：轻微、克制、清晰或单次爆发。爆发后必须收束，不能全片维持峰值。
8. **主导轨**：眼神、面部、头肩、手、身体重心、呼吸声线只选一个做主角。
9. **辅助轨**：最多一到两个支持细节，不能六轨同时抢戏。
10. **可见节拍**：按时长只记录 1–3 个“策略 → 可见变化”，不固定要求 2–4 个节拍；短镜头可以只有一次策略变化。
11. **结束状态**：写清姿态、视线、手中物件、呼吸和要交给下一镜的痕迹。

新建或重写的复杂表演镜头使用 `actingControlVersion: 2`。除上述顺序外，再把表演拆成四个可检查结构：

1. `performanceArc`：人物原先维持的保护策略、击穿它的画内触发、暴露出来的可见状态、人物主动选择、对方/道具/环境反馈、人物如何回稳或失败；
2. `hasDialogue` 与 `dialoguePerformance`：显式声明当前镜是否有对白；有对白时逐句记录台词全文、说话人、反应人、触发动作或关键词、重音短语、说前状态、可见反应、声音/呼吸/停顿和说后状态；禁止从 `voiceBreath` 猜测是否有对白；
3. `performanceEnvelope`：任何爆发表演，或 `clear` 档且面部主导、需要观众明确读到峰值的表演，必须写进入、峰值、退出；`micro` 或 `restrained` 镜头不强制凑齐三相；极短窗口若无法容纳三相，必须把强度降为 `micro` 或 `restrained`，不得保留 `clear` 标签再用文字证据豁免；
4. `prohibitedEarlyReactions`：明确哪位 `respondingCharacter` 的哪项反应在何种触发出现前不得发生，防止守卫串到错误人物或人物提前变脸、转头、接物。

这四项是导演计划和机器检查，不是提示词标题模板。`facialCalibration.observableAction` 可保存自然语言面部观察；可选 `facsAuHints` 只作内部审计，禁止进入视频模型正文。同一 AU 在不同处境中不能被当作固定情绪公式。

## 4. 六轨的使用方法

| 轨道 | 可执行写法 | 常见假人写法 |
|---|---|---|
| 眼神 | 先看物件，再短暂抬眼，又把视线压回桌面 | 眼神充满悲伤 |
| 面部 | 单侧嘴角想抬起又收住，下颌随吞咽松开 | 表情复杂而高级 |
| 头肩 | 目光先转，头部稍后跟上，呼气时肩膀落下 | 她自然地转头 |
| 手部 | 手伸到一半停住，指尖收回并揉皱衣角 | 双手表现紧张 |
| 身体 | 重心先后撤，脚步随后退开并重新站稳 | 她害怕地后退 |
| 呼吸声线 | 鼻腔短吸气，停半拍，压低声音说完，尾音收住 | 她用悲伤语气说 |

每个短拍使用：`一个主动作 + 一到两个辅助细节 + 一个物理或呼吸结果`。表演不是六项清单；删掉任何不服务戏眼的动作。

## 5. 真人感硬规则

1. 情绪必须由当前可见或可听事件触发，禁止无原因摆拍。
2. 眼神通常先于头部和面部变化；身体稍后承接，避免五官同时换成标准表情包。
3. 至少保留一个真实的不完整过程：手伸出又停、话到嘴边咽回、笑只出现半边、回头只完成一半。
4. 动作必须有重量和后果：杯子落桌后液面轻晃，转身后发尾延迟摆动，长呼气带动胸腔和肩膀落下。
5. 高潮不等于动作最多。突然静止、一次吞咽或停止重复动作也可以是高点。
6. 呼吸与强度同步；激烈表演不能胸腔不动，克制表演不能一直急喘。
7. 泪痕、红眼、乱掉的呼吸、手中物件和身体朝向必须跨拍保留，不能下一拍自动复位。
8. 镜头和光线服务同一个表演意图；情绪镜头默认减少无动机环绕、甩镜和多重运镜。
9. 手脸脆弱时，简化手指和口型，把情绪交给一个道具、呼吸或身体停顿。
10. 不把身份、发型、服装和五官写成情绪变化的一部分；人物资产继续负责外观锁定。

## 6. 复合情绪

复合情绪不平均分配：一个主情绪控制眼神、头肩和身体；另一个只从一个“破绽”泄露。

- 又气又委屈：身体和视线保持对抗，只让下眼睑水光或揉皱衣角泄露委屈。
- 笑中带泪：呼气后嘴角轻抬，但泪痕和红眼保留，不让笑覆盖悲伤。
- 害怕但强装镇定：身体站稳、声音压平，只让吞咽或指尖轻颤泄露恐惧。
- 嘴硬心软：台词拒绝，重心、停住的手或回看的眼神却没有真正推开对方。

## 7. 多角色纪律

- 每拍只有一个焦点人物获得主表演动作。
- 对方先完成触发，焦点人物确认接收到后再反应；禁止提前变脸。
- 非焦点人物只保持持续微动作：自然呼吸、眨眼、视线停留、衣摆轻动。
- 禁止所有人同时转身、哭、挥手、起立或说话。
- 物件控制权一次只属于一只明确的手；递接动作分为拿起、伸出、看见、接触、松手、收回。

## 8. 讲戏与提示词的硬衔接

命中本 DLC 的 Shot 必须在 `shot_narration` 中设置：

```json
{
  "performanceMode": "emotion_dlc",
  "performancePlan": {
    "dlcId": "emotion-performance-v1",
    "actingControlVersion": 2,
    "templateSource": "knowledge/capabilities/dlc/emotion-performance.md",
    "skillsApplied": ["seedance2-prompt", "seedance-characters"]
  }
}
```

完整字段见 `templates/project/shot-narration-input.json`。`narration-lint` 检查表演结构和抽象情绪污染；`performance-capsule` 把完整计划归档为审核证据。最终 Seedance 提示词只绑定当前镜可见的 `performance-continuity-v1`：v2 增加“禁止提前反应”时间守卫，并继续带结束状态与连续保留；完整胶囊、FACS/AU 和内部策略字段不得直接混入正文。

新建或重写的 `emotion_dlc` 计划必须填写 `actingControlVersion: 2`、`hasDialogue`、`obstacle`、`tactic`、`beatPlan`、`performanceArc` 与 `prohibitedEarlyReactions`；`hasDialogue: true` 时必须填写 `dialoguePerformance`，每条的 `stressPhrase` 必须属于 `lineText`，`respondingCharacter` 不得等于 `speaker`，并由一个同人物、`stressPhrase` 规范化完全相等的守卫禁止提前反应；`hasDialogue: false` 与任何明确说出台词的 `voiceBreath` 或 `dialoguePerformance` 同时出现都直接 FAIL。任何 `explosive`，或 `intensity: clear` 且存在面部主导/校准时必须填写 `performanceEnvelope`；极短窗口若装不下三相，必须降为 `micro` 或 `restrained`。旧项目缺这些字段仍可读取但始终给升级提醒；workflow v2 的当前写入会被 `narration-lint` 阻断，只有历史读取路径兼容。

导演内部的 `objective` 和 `subtext` 不进入模型胶囊；它们只负责帮助 AI 选择正确行为，避免把内心小说写进视频提示词。

## 9. 不增加的东西

- 不新增人工审核门；讲戏机审通过后自动锁定，最终提示词随现有生成前审核一起看。
- 不默认制作表情宫格；只有镜头和模型确实需要、且资产计划证明有用时才做。
- 不把整个情绪库放入每个项目上下文；只加载当前镜头需要的 DLC。
- 不让 DLC 改写门2已锁定的剧本、人物立场、台词、结局和分段。
- 不承诺一次生成即可达到某种奖项级表演；v2 只提高指令的因果、时序与可检查性，实际效果仍须经过生成后 Gate 5 审片或受控 A/B 验证。
