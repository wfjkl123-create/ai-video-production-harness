# LibTV 生成稿审片与改写

## 定位

把 LibTV 刚生成的视频当作“生成稿”，在它成为最终成片前完成一个闭环：

```text
看完整视频 → 找到可见问题 → 判断根因 → 选择最低成本修法 → 必要时重写提示词 → 准备下一次生成 → 等用户验收
```

不要把本 Skill 变成单纯的提示词语法检查。提示词写得完整，不代表视频执行正确；机器元数据 PASS，也不代表表演、肢体、产品或剧情 PASS。

## 默认说话方式

直接输出，不使用安慰、夸奖或缓冲句。每个问题固定回答：

1. **问题**：观众实际会看到或听到什么错误。
2. **原因**：证据支持的根因；证据不足时写“最可能原因”并标明不确定性。
3. **修复**：下一步具体改什么，优先给最低成本且能解决根因的方案。

用普通创作者听得懂的话。必须使用专业词时，紧跟一句白话解释。不要把分数、表格或术语放在结论前面。

完整输出格式见 [plain-language-output.md](references/plain-language-output.md)。

## 权威边界

- 本 Skill 负责看视频、找根因、选择返工面、形成改写约束和验证下一版。
- 所有 Seedance/即梦提示词正文的生成、重写、优化和润色，只能调用 `manifests/skills.lock.json` 中声明的 `seedance2-prompt` canonical Skill。本 Skill 不贡献提示词正文，不自创模板。
- 所有 LibTV 画布、节点、素材和模型操作，只能使用 `manifests/environment.manifest.json` 声明的官方 `libtv` CLI；命令以当前 `--help` 为准。
- 项目内已有成功 run 时，优先使用 `node src/cli.js prepare-video-audit --project <项目目录> --run <run-id>` 生成绑定 SHA 的机器审片包。它只做元数据、抽帧、黑帧、冻结、静音等基础检查，不能代替播放级导演审片。
- 不把原始生成尾帧升级为人物、产品或场景身份权威。尾帧只证明当时的站位、姿态、视线和运动状态；下次生成仍需绑定 canonical 基准。

## 1. 锁定本次审查对象

先确认正在审查的确切视频，不猜文件或画布节点：

- 本地视频路径或项目中的 `libtv_video` 成功 run；
- 对应的提示词版本、生成参数和实际绑定素材；
- 当前段锁定的剧情、Shotlist/一镜到底计划、人物/产品/场景基准；
- 若为复刻或修改，原视频在任务中是事实权威还是只提供灵感；
- 用户已经指出的问题，作为待核验线索，不自动当成全部问题或既定根因。

输入缺失时仍可做受限审查，但必须说明缺口怎样限制结论。例如只有视频、没有原提示词时，可以确认“第 7 秒背景消失”，不能确认一定是提示词漏写。

审查开始时记录并读回以下绑定；缺少哪项就明确标记哪项未知：

- 本地视频路径、文件 SHA、完整播放是否成功；
- LibTV 画布 UUID、生成节点 `nodeKey`、结果或任务标识；
- 原提示词路径和 SHA、实际参数、上游素材顺序及各自 SHA；
- 当前操作是否支持局部编辑、延长或只重做某个时间窗口。

需要从画布定位结果时，使用显式画布参数做只读查询：`libtv node list -p <画布UUID>`，再用 `libtv node -p <画布UUID> <精确节点名或nodeKey>` 读取节点、`data.results`、参数和入边。不要为了审片执行会写 `.libtv/project.json` 的 `libtv project use`；只有用户明确要求持久绑定当前目录时才使用它。

查询并确认节点或结果身份后，先运行 `libtv download --help` 核对当前语法，再用 `libtv download -p <画布UUID> -n <精确节点名或nodeKey> -o <专用审片目录>` 下载。下载后计算文件 SHA、记录本地路径并完整播放。下载失败或 CLI 结果身份无法唯一对应时，才回退到 Harness 已登记或用户提供的本地文件；不得自造 HTTP 请求、猜测 URL 或把留存帧当作完整视频。

用户上传新视频且尚未进入 Harness 时，先走项目的确定性 `intake-video` 入口并持久化 `routeDecision`。已经登记的 LibTV 生成结果不重复创建项目。

## 2. 先看全片，再看问题窗口

按这个顺序检查：

1. 用正常速度、有声音地完整播放一次，先判断故事是否看得懂、人物是否像在真实反应、产品是否承担剧情作用。
2. 核验时长、分辨率、画幅、音轨、文件 SHA 和实际生成参数。
3. 检查首帧、关键转折、接触动作、产品展示、段尾和拼接点。
4. 对发现问题的最小时间窗口加密查看；动作或接触无法判定时才逐帧，不对整段盲目全帧分析。
5. 对照提示词、素材职责和锁定剧情，检查模型是没有执行、执行错了，还是上游要求本身就有问题。

不得只看均匀抽取的几张帧图后宣布整段通过。快速抽帧可能漏掉一闪而过的多手、穿模、人物换位和背景突变。

把“审片完整度”和“返工决定”分开记录：

- `完整审片`：确切视频可完整播放，声音和关键窗口均已检查。
- `部分审片`：只能播放部分区间、只有抽帧或缺少声音；只能对已看证据下结论。
- `仅依据用户描述`：未取得确切视频；可以判断用户报告的问题若属实将导致返工，但不能声称已经独立审完整片。

即使审片不完整，一个已证实的致命问题也足以判定“当前版本必须返工”；这不等于 Gate 5 全片审查完成。

## 3. 按观众能感知的维度审片

必须覆盖以下方面；具体“现象 → 根因 → 修法”映射见 [defect-to-fix-map.md](references/defect-to-fix-map.md)。

- **开场是否看得清**：主体占画面多大；当前分辨率能否支撑脸、手、产品细节。
- **世界是否连续**：背景人物、帐篷、门窗、光向、影子、天气、道具是否突然消失或重建。
- **人和产品是否还是同一个**：脸、发型、服装、产品颜色、结构、比例和材质是否漂移。
- **动作是谁做的**：执行者、受力者、接触顺序、起点、过程和终点是否正确；是否有人凭空出现或动作瞬移。
- **人物是否像活人**：触发后有没有视线、呼吸、停顿、重心、微表情和对方反应；是否全程保持一个表情。
- **手、肢体和穿戴是否成立**：手指数、手臂来源、肢体穿插、布料与身体接触、穿脱物理是否正确。
- **摄影机是否讲得通**：机位、轴线、景别、主体大小和主运镜是否连续；运镜是否服务事件。
- **声音是否属于画面**：说话人、口型、台词、音色、环境音、距离和动作声是否对应。
- **结尾能否交给下一段**：位置、朝向、视线、道具、动作惯性和声音是否能连续接上。
- **故事是否完成任务**：冲突、情绪变化、关系变化和产品结果是否真正出现在画面中。

## 4. 根因只能落到可修复的层

每个问题只选择证据最强的主根因，必要时列一个次要可能：

1. `asset_or_first_frame`：首帧、人物图、状态图或产品图本身让模型难以执行。
2. `prompt_semantics`：动作主体、因果、情绪过程、空间或素材职责写错、漏写或互相冲突。
3. `timing_overload`：同一时间塞入过多对白、动作、反应或运镜。
4. `parameter_or_mode`：分辨率、时长、模型版本、模式或媒体顺序不适合任务。
5. `model_execution_variance`：输入合同合理，但这次生成偶发未执行或出现随机畸形。
6. `editing_or_join`：单段本身可用，问题只在裁切、音频、遮挡、拼接或节奏。
7. `unknown`：证据不足，不能可靠归因。

不要因为换了写提示词的模型就自动把失败归咎于模型；先用视频、原提示词和实际绑定素材证明因果。不要用更长提示词掩盖错误首帧、错误动作主体或不适合的生成模式。

## 5. 选择最低成本修法

按以下顺序判断，不默认整段重做：

1. **保留**：没有影响使用的问题，进入 Gate 5 人工验收。
2. **剪辑修复**：裁切、缩短、遮挡、调音、换一句音频或拼接即可解决，且不会破坏故事。
3. **局部换素材**：问题来自首帧尺度、错误状态图、产品结构或污染参考，只修对应资产和绑定。
4. **重写提示词**：动作主体、因果、表演、连续性或素材职责存在实质错误。
5. **调整参数或模式**：任务需要更高分辨率、不同 operation、拆段、编辑或延长路线。
6. **重新抽取一次**：仅在输入合同已被验证正确、问题属于偶发执行失败，而且用户明确接受再次付费时考虑。

同一问题可能有多种修法时，明确推荐一个，并说明为什么它最省成本或最稳。不要把工程参数交给用户选择。

推荐“只重做某几秒”前，先从节点读出实际 `model`、`modeType` 和参数，再用 `libtv model <精确模型名>` 读取当前 `tool_spec`，核验该 operation 确实支持对应的局部编辑、延长或视频编辑能力。若证据只能证明整段重新生成，或当前能力仍未知，就直接写“只能整段返工”或“局部重做能力未核实”，不能把剪辑范围误写成生成能力。

## 6. 需要重写提示词时

1. 先形成“改写任务单”：失败发生时点、可见错误、正确主体、空间、结束状态、必须保留内容和禁止复发项。它是诊断输入，不是提示词正文。
2. 完整读取并调用 canonical `seedance2-prompt` Skill 及它为当前版本或 operation 要求的参考文件。
3. 从故事因果和导演预演重新编排，不做“原提示词顶部加一段说明”式修补。
4. 只修导致失败的层，避免为了显得专业加入无关动作、运镜或形容词。
5. 完成项目规定的镜头编排自检、提示词语义自检、机器 lint 和独立审查。
6. 保存原提示词、失败视频和修订证据；新提示词使用新版本、新 SHA 和新生成指纹。

## 7. 写回 LibTV 与付费边界

- 可以读取画布、下载结果、核对节点、上传已批准素材、更新提示词和参数，并把下一版准备到待生成状态。
- 写回前核对确切画布、节点、素材顺序、提示词 SHA、模型、时长、分辨率和声音设置；写回后读回验证。
- 默认停在用户检查并点击“生成”的位置。
- 只有用户在当前对话明确说“允许/批准你提交这次视频生成”时，才能提交一次与当前指纹完全一致的生成。普通“继续”“按推荐做”“把前期准备好”都不是付费授权。
- 不自动对同一节点、模型或指纹付费重试；不删除失败视频或旧提示词。
- 保留失败视频、原提示词、run 和节点终态、生成参数、素材绑定、package SHA、机器检查、独立审查和修订闭环；不得只保留最后成功版。

## 8. 正式审片结论的复核与 Gate 5

- 普通对话里的初步判断可以直接反馈；它不是 Gate 5 批准。
- 准备提交正式审片结论前，先完成产出者自检，并由至少两名不同于产出者的独立 Agent 分别审查。复杂剧情、多人关系、复刻或跨段交付固定使用三名独立 Agent，分别覆盖：需求或源事实忠实度、导演表演与镜头因果、交付完整性与连续性边界。禁止由同一 Agent 自称完成多条独立路径。
- 任一实质 FAIL 先修订并对受影响维度复审，不能靠投票通过。
- 正式 Gate 5 在 Lavish 审核页向用户展示：直接结论、问题或时点证据、原因、修复、产出者自检结论、各独立 Agent 的 PASS/FAIL、已修订闭环和剩余风险。
- 只有用户在 Gate 5 明确批准后，才允许把视频锁定并自动进入下一段。机器检查、独立审查或普通对话中的“可以用”都不能替代用户批准。

## 9. 完成标准

只有同时满足以下条件，才能称本轮审片完成：

- 已明确标记审片完整度；只有 `完整审片` 才能声称全片已审；
- 每个实质问题都有“问题、原因、修复”和可追溯时点或帧证据；
- 已区分观察事实、根因推断和用户业务选择；
- 已给出明确结论：保留、剪辑修复、换素材、重写提示词、调参数或证据不足；
- 若发生重写，新正文来自 canonical `seedance2-prompt`，并绑定新版本和验证证据；
- 若写回画布，节点已读回核验，且没有未经授权提交付费生成；
- 正式审片结论已完成要求的独立复核；
- 最终是否通过 Gate 5 仍由用户在 Lavish 人工验收，不由本 Skill 代替用户批准。
