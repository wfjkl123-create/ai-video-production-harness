# 给用户的默认输出

## 固定顺序

```text
审片状态：【完整审片 / 部分审片 / 仅依据用户描述】
结论：这版属于【可直接验收 / 剪辑后可用 / 必须返工 / 证据不足】。

问题 1
- 问题：[可见或可听的错误]
- 原因：[已经核验的主根因；没有核验则写“最可能原因”或“根因待核对”]
- 修复：[换哪张图、改哪段动作、调整哪个参数或采用哪种剪辑]
- 证据：[本次视频的真实时点或帧文件；没有播放证据则写“来自用户描述，未独立复核”]

问题 2
- 问题：……
- 原因：……
- 修复：……
- 证据：……

先做什么：[按影响和依赖关系写第一步]

下一步：[明确保留、剪辑、换素材、重写提示词或调参数；准备画布时停在生成按钮前]
```

## 表达规则

- 开头直接给能不能用，不写“整体不错”“有一些小问题”“你的方向很好”。
- 按影响排序，不按检查清单排序。致命穿帮、故事错误和产品错误优先。
- 一个问题只写一个主根因；不能确认时写“最可能原因”，不要装成确定事实。
- 修复必须是动作：换哪张图、删哪段动作、重写谁做什么、保留哪几秒、调整哪个参数。
- 用户没有要求时，不展示百分制、权重、JSON 字段名或英文故障分类。
- 问题很多时，先列所有必须修复项，再列可接受的小瑕疵。不要为了简短隐藏问题。
- 模板中的方括号只是占位符。禁止复用其他案例的时间、人物、场景、根因或修复范围。

## 结论的含义

- **可直接验收**：未发现影响目标的实质问题；仍等待用户 Gate 5 决定。
- **剪辑后可用**：生成内容本身成立，问题可通过本地无损或低风险剪辑解决。
- **必须返工**：人物、产品、剧情、动作、连续性或音画出现不可接受错误。
- **证据不足**：缺少原提示词、素材、声音、完整视频或可播放证据，无法可靠判断根因或全片状态。

“必须返工”和“完整审片”不是一回事：仅凭一个已证实的致命错误就可以判定当前版必须返工，但没有完整播放就不能声称其他区间也已审完。

## 用户先看过视频时

把用户的反馈作为“重点复核项”，逐条验证：

- 用户判断正确：补充时点、根因和修法。
- 用户描述了现象但归因不成立：直接纠正归因，并说明证据。
- 用户漏掉了更严重的问题：先报告更严重的问题，不被用户列出的范围限制。

## 用户尚未看视频时

先独立完成全片审查，再让用户只看标出的关键时点。不要要求用户先完整审一遍才能启动 Skill。
