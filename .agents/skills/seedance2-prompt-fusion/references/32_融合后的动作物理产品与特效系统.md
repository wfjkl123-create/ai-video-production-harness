# 融合后的动作物理产品与特效系统

本文件融合原 Skill 的动作链、接触受力、产品身份、粒子/巨物/能量/形态变化，与 v6.7 motion、model mechanics、event density、VFX、I2V/R2V 和 first-last-frame 方法。

## 1. 所有变化都写成物理因果

```text
初始状态 → 触发/力源 → 接触点与运动路径 → 主体反应 →
道具/衣料/环境后果 → 过冲或回稳 → 明确终点与残留状态
```

动作先锁对象数量、谁作用于谁、画面方向、接触关系和终点，再写速度与风格。跳跃、碰撞、递物、穿脱、变形和特效都不能只写开始与结果。

## 2. 复杂度使用同一保真预算

人物身份、产品结构、手部接触、剧烈运动、镜头运动和多事件会争夺同一稳定性预算。身份或文字越重要，动作、运镜和事件数越要收敛。短镜头只选一个主要事件；多个独立变化触发拆镜，不用时间轴硬塞。

## 3. 产品是稳定主体，效果绕它发生

产品的形状、比例、颜色、logo/标签位置、结构和材质由 canonical 资产负责。默认让光、液体、蒸汽、粒子、手或摄影机围绕产品运动，不让产品本体无故融化、拉伸或重构。确需变形时，明确可变区域、保持区域、阶段、数量和终态。

## 4. 特效必须进入世界

- 写来源、材质、运动路径、与主体/环境的交互及结束状态。
- 发光必须照亮附近表面并形成遮挡、反射或曝光变化。
- 粒子具有尺度、阻力、重力/浮力与消散方式，不是贴图层。
- 巨物用超框、遮挡、空气透视、地面后果和人物延迟反应证明尺度。
- 首尾帧只定义可观察的边界状态；中间仍要有可执行因果，不把插值当作自动合理。

## 5. 双方差异的统一裁决

- 原 Skill 的六步形态链与 v6.7 motion/event-density 合并为“单主事件 + 完整后果”；特效词库只能按物理需要选取。
- 原“产品是演员”保留，但 v6.7 的 identity lock 优先：动效不能以牺牲标签、轮廓和材料真实性换取炫目。
- 负面约束只封最高风险；优先写正向保持区、接触点和终态，不反复点名污染元素。
- 第一帧/尾帧、视频运动参考和文字动作各自只控制获授权维度，不让运动参考迁移人物、背景或产品外观。

## 6. 动作与特效验收

- 力从哪里来，接触在哪里，谁被动反应，什么被永久改变？
- 是否能看见动作的中间过程与恢复，而非瞬移？
- 是否只有一个主要变化，保真预算是否超载？
- 产品不可变项是否早于特效声明，效果是否真实照亮/影响环境？
- 结束数量、位置、朝向、材质状态和惯性是否明确？
