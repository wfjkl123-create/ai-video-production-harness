# Seedance 2.5 自适应控制与 30 秒对白密度

> 本文件是导演生产规则，不是官方能力声明。官方四部分骨架、参数与 operation 边界仍以 refs 11–24 为准。第三方教程只提供待验证的经验候选，不能直接升级为模型硬规则。

## 1. 先选最低充分控制强度

不要给所有任务套同一套长模板。选择能保护结果的最低控制强度；控制越细，越要为每条约束承担时间和冲突成本。

| 等级 | 适用 | 写法 | 不要做 |
|---|---|---|---|
| L1 自由生成 | 单主体、单场景、单动作、无精确对白或卡点 | 一句话概述 + 连续动作 + 主要镜头 + 全局补充 | 为简单镜头强行切成秒表 |
| L2 顺序导演 | 有明确镜头顺序、反应镜头或信息揭示，但落秒不关键 | `CUT 1 / CUT 2 / CUT 3`，每镜写因果与结束状态 | 用大量一秒插入镜头挤掉表演 |
| L3 时间轴导演 | 多人物对白、两场以上、反转必须落点、音乐卡点、复杂资产进入/退出 | 连续时间区间，覆盖总时长；逐段写开始、触发、动作、反应、声音和结束状态 | 把时间戳当装饰，或让台词超过区间 |

出现下列任一情况，至少使用 L2；出现两项以上或结尾必须精确落点，使用 L3：

- 两名以上角色互相反应；
- 两个以上地点或明显时空切换；
- 一句台词必须在指定动作前后说完；
- 某个道具需要明确进入、交接或退出；
- 观众知道、角色不知道的信息差；
- 结尾反转后必须保留可见反应；
- 音乐、口型、动作或剪辑需要同步。

控制等级只写入导演预演或审计记录，不要把 `L1/L2/L3` 标签塞进模型提示词。

## 2. 先分配时间，再写台词

30 秒不是 30 秒对白。先从总时长中划出：

1. 观众理解人物与场景的建立时间；
2. 说话人的自然发声时间；
3. 听者的可见反应和停顿；
4. 切场、坐下、拿放道具等不可压缩动作；
5. 结尾关系变化后的停留时间。

按目标声线和情绪把台词实际读一遍，或用对应语速试听；不要依赖统一“每秒多少字”的硬公式。含犹豫、电话压缩、哭腔、笑场或重音的台词必须留更多时间。读不完时按顺序处理：

1. 删除重复信息；
2. 合并同类条件或动作；
3. 用一个可见动作替代一句解释；
4. 减少镜头，而不是加快到不自然语速；
5. 仍放不下时拆成下一 Generation 或改用超长入口。

对话段逐句写成：

```text
时间区间 + 说话人 + 说话前动作/视线 + 台词 + 听者反应 + 段尾状态
```

一人说话时，另一人保持明确的听者状态。不要让听者在同一秒同时完成多次独立反应。笑意升级应拆成不同载体，例如嘴角收住 → 低头遮掩 → 端杯挡住，而不是每段重复“偷笑”。

### 2.1 多人对白的开场、群像与切镜

下列是导演性稳定建议，不是模型能力承诺；只在多人、切镜或口型是核心验收项时使用：

- 首拍从一个已在发生的可见状态或被触发的动作开始，避免用空景或静止摆拍占掉台词段的建立时间。
- 每个可见但不说话的人只给一个低成本的听者反应（看向说话人、点头、收住表情、托稳道具之一）；群像不冻结，也不要求所有人同步做复杂动作。
- 场景、轴线或前后景关系重置时，先重新写清当前说话人、听者、屏幕左右位和道具接触，再进入下一句；不要把上一镜的空间关系当作模型已知。
- 30 秒多镜任务可以指定一个已绑定的人物或场景素材作为跨段视觉锚，但只有当身份/空间漂移风险真实存在时才增加，不得为了“长片格式”虚构额外资产。

## 3. 每段使用六项节拍合同

L2/L3 的每个节拍至少回答：

```text
开始状态 → 触发事件 → 主体动作 → 对方/环境反应 → 摄影机响应 → 结束状态
```

- **开始状态**：人物、道具、视线、摄影机从哪里继续。
- **触发事件**：为什么此刻开始行动或说话。
- **主体动作**：起点、过程、终点；不留瞬移。
- **对方/环境反应**：听者、受力物、衣料、光或声音怎样响应。
- **摄影机响应**：只在剧情需要时切、推、摇或保持不动。
- **结束状态**：下一段可以直接继承的站位、朝向、道具、惯性和情绪。

结束状态不是重复总结，而是连续性输入。HARD CUT 后必须重新锚定左右位、轴线、道具和视线。

## 4. 多模态素材使用六字段职责

有素材时逐项记录：

```text
负责什么：唯一主要职责。
保留范围：当前素材允许锁定的可见属性；人物默认包含完整可见身份，除非用户明确缩窄。
禁止迁移什么：背景、姿势、人物、字幕、水印、原台词等污染源。
生效区间：全片或明确时间段。
优先级：与其他素材冲突时谁是身份/空间/动作/声音权威。
退出状态：素材对应对象何时离场，后续是否继续保持其身份或状态。
```

模型提示词只保留执行所需的自然语言，不必显示字段名。平台编号按实际上传顺序编译。

用户给案例或示例时，再记录“允许迁移维度”。只说“参考结构”仅迁移层级与信息粒度，不默认迁移故事、角色、镜头、视觉风格或素材范围。

不要固定要求 12 张人物图或“所有视频必须先做资产”。按风险选择最小充分资产：

- 纯文生能稳定表达的原创镜头，不虚构参考素材；
- 身份刚性高时增加人物身份图；
- 产品结构或不可见面重要时增加必要角度；
- 多张独立角度与一张人物板按主体数量、清晰度和入口限制选择；
- 视频、音频输入会改变成本和职责时，先遵守项目授权边界。

## 5. 把人物、声音、台词和时点分开

- 人物图回答“是谁、长什么样”；
- 音频回答“音色、音高范围、语速、停顿和情绪质感”；
- 文本回答“说什么”；
- 时间轴回答“什么时候说”；
- 说话人绑定回答“由谁说”。

不要声称人物板会自动携带稳定声纹，也不要承诺“精确复制声音”。音色参考应尽量单人、干净、无 BGM 和强混响；多人一人一声线。生成后分别验收说话人、ASR、口型、音色漂移和噪声。

## 6. 正向锁定优先，排除项只封高风险失败

先写目标状态，再写贯穿保持项，最后只列会破坏成片的排除项。

```text
目标：男人始终坐在女人对面，压住笑意并保持听者状态。
保持：饭店内女人在画面左侧、男人在右侧，机位不越轴。
排除：母亲只以电话声音出现；无字幕、无克隆人物、无串词。
```

不要实行“绝对正向”或“否定词越多越好”。`无字幕`、`禁止串词`、`不要迁移背景` 等明确排除可以保留；先用正向画面承担主要控制。

## 7. 拒绝没有证据的伪精确

以下内容只有在当前官方资料、当前平台或可复现测试支持时才能写成规则：

- 固定 FOV 角度表必然提高稳定性；
- 所有速度必须使用 km/h；
- 雾、遮挡和抖动必须使用固定百分比或厘米；
- 白平衡 Kelvin、鞭甩秒数或镜头顺序是模型硬语法；
- 画面外未编辑区域可以逐像素完全不变；
- 某一分辨率或素材上限永久不变。

没有证据时，使用观众可见的自然语言和剧情动机。数字只用于真实时码、已验证参数、空间交接或用户明确要求的测量目标。

## 8. 把生成、修复、延长和复用看作一个闭环

写提示词前同时规划失败后的最小修复路线：

| 结果 | 优先动作 |
|---|---|
| 故事正确，局部物体错误 | 局部编辑，只声明修改对象、时序和保留项 |
| 人物/构图正确，道具错误 | 对象替换或标注编辑 |
| 颜色、BGM、字幕错误 | 对应专项编辑，不重生成整片 |
| 某段或某帧很好 | 截取后作为下一次已绑定输入，明确只继承什么 |
| 需要继续剧情 | 继承真实末态，同时绑定 canonical 人物/产品/场景锚 |
| 超长内容信息过密 | 拆段延长或多 Generation；不要让一个提示词包办全部细节 |

编辑提示词要求“非目标区域在感知、结构、时序和光线上的一致”，不要承诺逐像素不变。生成后的真实视频、真实末帧和播放级声音才是下一轮诊断证据。

## 9. 模型正文与审计记录分离

模型正文只保留本次生成可见、可听、可执行的信息。以下内容留在审计文件：

- 控制等级与选择原因；
- 证据等级、来源坐标和第三方材料；
- 对白试读结果与删改记录；
- 素材 SHA、上传顺序和平台参数；
- 结构/语义/双源验证报告；
- 生成失败与修复路线。

不得把“十四字段合同”“验证 PASS”“参考某文档”“沿用上版”等元数据写进模型提示词。

## 10. 交付前检查

```text
□ 是否选择了最低充分控制等级，而不是默认最大控制？
□ 所有台词是否按目标语速真实读得完，并保留听者反应？
□ 首拍是否已经有可见事件或人物状态，而非空景等待？群像中每个非说话者是否只承担一个可见反应？
□ 是否先建立人物/场景，再开始密集对白？
□ 反转台词后是否有可见反应和停留？
□ 每个节拍是否有开始、触发、动作、反应、camera 和结束状态？
□ 素材是否有唯一职责、保留范围、生效区间、优先级和退出状态？
□ 案例/示例是否只迁移了用户明确允许的维度？
□ 人物、声音、台词和说话时点是否分别绑定？
□ 是否正向锁定优先，只保留必要排除项？
□ 是否删除无证据的固定摄影数字和能力承诺？
□ 首次生成失败后，是否已有最小编辑/延长/复用路线？
□ 模型正文是否没有审计标签、来源历史和未绑定指代？
```
