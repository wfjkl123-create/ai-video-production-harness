# 融合后的需求访谈与提示词编译系统

本文件深度合并原 Skill 的八要素、控制强度、素材编译、细节导演引擎，与 v6.7 的 interview、interview-short、prompt、prompt-short、Director Formula、intent-vs-precision 和 prompt compiler。目标不是把愿望润色成长提示词，而是把它编译成模型可执行、用户可验收的镜头合同。

## 1. 先识别用户，不先发问卷

- 无明确想法：给 2–4 个完整可选方向或先提一个小方案，允许“你决定”。
- 有粗略想法：只问会改变主体、结局、素材、时长、画幅或 operation 的缺口；已有答案不重问。
- 专业用户：原样保留其镜头、焦段、调度、表演和交付术语，只补遗漏，不把专业决定重新改写成大众选项。
- 单镜快速任务最多追问 3 个关键问题；复杂任务一批不超过 5 个。每问必须有默认值，回答“不知道”不能让流程停住。

## 2. 愿望到任务的统一编译链

```text
用户愿望 → 识别已锁事实与真实未知 → 判版本/surface/operation →
判 narrative/non_narrative → 形成观众会看到的 mini-treatment →
分配素材权威与控制强度 → 建立节拍/镜头合同 → 压成自然生成正文 → 验收合同
```

原 Skill 的八要素用于检查完整性；v6.7 Director Formula 用于排序。统一后先写“主体及本镜唯一变化”，再按风险补环境、摄影、光、声音、素材职责和约束。八项不是八栏表，缺乏作用的字段不硬填。

## 3. 精度由风险决定

- L1 自由生成：单主体、单动作、低连续性风险，写一条连续导演指令。
- L2 顺序 CUT：顺序和反应关系重要，但不要求精确落秒。
- L3 时间轴：对白、音乐、信息差、转场或多人物同步必须校准时码。
- 只有用户实测、当前 UI、真实素材时长或必要交接支持的数字才进入正文；其余用可见结果表达，拒绝伪 FOV、速度、色温和百分比。

## 4. 内部合同与模型正文分离

内部可保存：版本、operation、Director's Read、素材权威矩阵、节拍预算、状态胶囊、拒绝俗套、验收项。模型正文只保留能看见或听见的载体，不出现 `L1/L2/L3`、隐藏目标、审计标签和工作流字段。

短提示词不是删掉因果，而是保留最小充分集：主体、唯一变化、动作终点、一个主摄影策略、动机光或声音、身份锁与最高风险约束。复杂提示词也不得用重复术语冒充控制力。

## 5. 双方差异的统一裁决

- 原 Skill 偏“直接产出最终中文成稿”，v6.7 偏“先访谈后编译”：信息已经充分时直接编译；关键未知会改变结果时才访谈。
- 原八要素强调覆盖，v6.7 强调意图与排序：覆盖服从意图，任何句子都要完成导演职责并封一个真实失败模式。
- 原细节引擎允许补足微观导演选择，v6.7 要求不重问已知：不改变故事、品牌和资产事实的摄影/动作细节可自主补；身份、产品结构、权利、时长和素材缺失不得编造。
- 用户原话与平台标签优先保真；内部可以翻译成专业合同，最终不改变其已经明确的创作决定。

## 6. 编译验收

- 是否能用一句话说清开头到结尾“什么变了”？
- 每个问题是否真的改变结果，是否重问了已给信息？
- 每个关键名词是否落成可见动作、空间、声音或材质证据？
- 控制强度是否最低充分，正文是否混入内部字段？
- 去掉“电影感、高级、自然、震撼”等形容词后，任务仍可执行吗？
