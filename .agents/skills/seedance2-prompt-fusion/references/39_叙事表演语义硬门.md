# 叙事表演语义硬门

本文件解决一种高频失败：提示词格式完整、素材绑定正确，也写了“自然、克制、被戳中”，生成的人却仍像背台词、等指令、盯镜头。原因不是形容词不够，而是正文缺少可以被模型执行的事件链。

## 1. 何时强制加载

出现任一条件即强制执行：

- 人物说话、听话或互相看向；
- 情绪、潜台词、冲突、关系变化或反转；
- 近景、反应镜头、剧情带货、短剧、爆款复刻；
- 用户要求真人感、活人感、微表情或去 AI 味。

纯产品转台、空镜、无人物材质演示不触发。不要给非叙事物体强加心理。

## 2. 每个关键节拍的七段可见链

进入本节前，先按 ref 44 读取当前人物身份包、Master Profile、story state、voice identity、scene geometry 和声音策略；对本 Shot 只选择被当前事件触发的 1–3 个长期习惯并做场景适配。没有当前锁定来源时明确缺口，不得凭对话记忆补成“角色一贯如此”。

正文必须按因果顺序提供：

1. **原本在做什么**：人物在事件发生前有自己的小任务，不能等导演喊开始；
2. **画内触发**：一句话、一个声音、一个物体或对方动作真正发生；
3. **注意力转移**：先眼睛、再头或身体，或刻意不转；必须写清目标；
4. **身体泄露/不完美**：呼吸、手指、下颌、肩膀、吞咽、语气、动作停顿中的一个具体变化；
5. **主动选择**：顶回去、忍住、回避、靠近、继续手头动作等；不是情绪自动播放；
6. **对方或环境反馈**：听者、道具、衣料、背景声音或摄影机对事件作出后果；
7. **恢复/末态**：人物没有定格，余波如何收住，并留下可继承的位置、视线、道具和关系状态。

不是每一秒都塞七个动作，而是每个关键节拍至少形成一条完整因果。动作少可以，动作无因果不可以。

## 3. 抽象情绪必须落到身体载体

“紧张、尴尬、被戳中、自然、克制、松弛、犹豫、开心、震惊”单独出现均不算表演指令。必须同拍绑定至少一个可见或可听载体，例如：

- 手指在包带上停住，拇指压力仍未松开；
- 先短促鼻息，再把已经张开的嘴收住；
- 眼睛先移向对方，头晚半拍跟过去；
- 回答前吞咽一次，音量比上一句低，但不低头；
- 对方听见后下颌轻收，原本准备接话的气口停住。

禁止把微表情写成无来源的动作菜单。眨眼、点头、嘴角变化必须由当前事件触发并改变下一步选择。

### 3.1 表演尺度必须服从画面可读性

- 远景/大全景优先用步幅、重心、肩背、停走、人与人距离和动作轨迹承载反应；不要把故事转折押在观众看不清的嘴角或眼睑上。
- 中景允许手部、上身、视线和面部共同承载；近景/特写才把呼吸、吞咽、下颌、眼睑和嘴角作为主要证据。
- 这不是按焦段机械分配表演。最终以主体画框占比、面部像素可读性、运动模糊和遮挡为准；同一焦段改变机位距离后，表演尺度也可能改变。
- 若用户同时锁定远景和微表演，先按 ref 41 判断能否通过提高画框占比、分镜切换或身体层证据兼容；不能兼容时必须指出取舍，禁止静默删除任一核心要求。

## 4. 对白是表演事件，不只是文本

每句对白都必须在同一时间段写清：

```text
说话人正在做什么 → 看向谁/哪里 → 开口前气口或动作 → 台词原文与声线 → 说后身体余波 → 听者同时反应
```

硬规则：

- 说话时默认看场内对象，不看镜头；转向顺序要具体。
- 听者不能等台词结束才恢复生命。至少有一个持续任务、注意力变化或被压住的反应。
- 两句连续对白之间必须有可见交接：沉默、呼吸、视线先行、动作停顿或道具接触，不得瞬时抢话。
- 产品名对白同时是一场关系变化：谁提出解决方案、对方为什么从防御变成愿意尝试，必须由画面动作证明。
- 不用“自然说出”“真实反应”“情绪递进明显”等结果词代替执行过程。

### 4.1 触发词与禁止提前反应

关键对白先确定真正改变听者的一个词或短语。听者在该词出现前继续原任务或维持保护策略；词出现后才允许注意力、呼吸、面部或身体改变。把最危险的一项提前反应写成明确禁止条件，例如“在听到‘钥匙’之前，她不抬头、不接钥匙”。

只有绑定真实对白音频、试读结果或可靠素材时码时才使用小数秒；否则用连续秒级区间或阶段顺序。禁止用无证据的 0.2 秒、0.7 秒等数字假装表演更精确。

### 4.2 复杂情绪不是开关

情绪转折必须能回答：人物原先用什么保护策略维持局面；哪个画内触发使策略破裂；真实状态从哪个可见破绽泄露；人物随后怎样选择并回稳。爆发性变化，或需要观众明确读到峰值的清晰面部主变化，须有进入、峰值和退出，不得从中性脸直接切到持续整段的标准表情。`micro` 或 `restrained` 的克制镜头不强制凑齐三相；极短窗口若装不下三相，必须降为这两档，并保留触发、变化方向和末态。

FACS/AU 只允许留在导演审计记录中辅助观察，不能进入最终模型提示词，也不能被当作固定情绪公式。最终正文只写镜头能看见的部位、变化、先后与退出。

## 5. Seedance 2.0 的最低时间轴合同

只要有两人对白、情绪转折或产品说服，最低使用 L3 连续时码：

- 时间段从 0 秒开始，按顺序无大空洞，覆盖声明总时长；
- 至少三个表演段：事件前生活状态、触发与反应、选择与末态；
- 每段只写能在该时长内完成的动作；短镜头宁可删动作，不压缩因果顺序；
- 每句台词放进自己的时间段，写出说话人和听者；
- 镜头、背景活人和声音只响应主事件，不抢台词。

## 6. 自动硬门

保存最终提示词后运行：

```bash
python3 scripts/validate_narrative_performance.py prompt.txt \
  --profile dialogue --duration 7 \
  --report prompt.performance-report.json
```

有说话台词使用 `--profile dialogue`；纯无对白关系或情绪表演使用 `--profile character-action`，不要为了通过检查虚构台词。

验证器检查：连续时码、可见因果词组、抽象情绪是否有身体载体、逐句说话人与听者反应、泛化动作和负面堆叠。报告记录文件 SHA；提示词任何字符变化都必须重跑。

自动 PASS 不是创意质量保证，只是阻止明显空洞稿进入下游。

交付、编译或准备画布节点前，必须再次验证报告仍绑定当前文件：

```bash
python3 scripts/verify_narrative_performance_report.py prompt.txt prompt.performance-report.json
```

## 7. 人工逐拍预演门

交付者必须对最终版本逐段回答：

1. 触发是否真的发生在反应之前？
2. 如果删掉情绪形容词，观众还能从身体看懂吗？
3. 说话时听者正在做什么？
4. 人物是否始终有明确视线对象，而不是默认看镜头？
5. 每段动作能否在给定秒数内由真人完成？
6. 产品出现是否改变了人物选择，而非突然插入展示？
7. 末态是否留下真实余波，而不是所有人一起停住或微笑？
8. 关键对白的触发词出现前，听者是否仍维持原任务，没有提前变脸或动作？
9. 复杂情绪是否经历保护策略、裂缝、暴露和回稳；爆发性或需要读到峰值的面部变化是否有进入、峰值和退出；极短窗口是否降为 `micro/restrained` 并避免强凑三相？
10. 最终正文是否只含自然语言可见动作，没有 FACS/AU 编号或情绪公式？

任一答案是否定，当前稿即 FAIL。

## 8. FAIL 后的重写规则

- 回到导演预演，先锁故事触发、关系变化和末态；
- 重排时间轴，再写可见动作；
- 最后才补镜头、环境、声音和少量负面；
- 不保留失败稿的动作骨架后只在顶部追加“她很尴尬”等说明；
- 不以增加形容词、眨眼次数、点头次数或负面词数量冒充真人感；
- 新稿保存为新版本并重新绑定 SHA，旧稿只保留为反例。
