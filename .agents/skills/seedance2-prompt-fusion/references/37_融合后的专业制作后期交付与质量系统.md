# 融合后的专业制作、后期交付与质量系统

本文件融合原 Skill 的生成、修复、延长、复用闭环与 2.5 operation 合同，和 v6.7 production pipeline、professional filmmaking、aspect/delivery、color、audio post、subtitles 及 QC 方法。

## 1. 阶段不能混称

```text
创意/brief → 资产与权利 → 导演预演 → prompt-ready → submitted →
generated → accepted take → edit/post → delivery QC → publish/ad approval
```

每次只报告有证据的阶段。文件存在、validator PASS、提示词已写、平台提交、生成完成、人工接受、导出成功和可投放是不同状态。

## 2. 专业生产合同

在专业或商业任务中记录：角色与审批人、目标 surface/territory、画幅/时长/版本、素材及权利、镜头与交付规格、颜色与声音交接、字幕/安全区、版本命名和验收责任。创意探索阶段不必把全套交付表塞给普通用户；一旦要求投放、交付或客户审核再加载。

## 3. operation 与后期职责

普通生成、延长、智能/高级编辑、局部编辑、BGM 分离、绿幕、白模和多宫格各有独立输入、保留项、可变项、失败线和验收。必须走对应 2.5 14 字段合同，不把一个 operation 的能力迁移到另一个。

生成负责画面与已验证原生声音；剪辑负责镜头选择、节奏、合成、遮罩和版本；调色负责色域、显示变换、镜头匹配和合法电平；声音后期负责编辑、降噪、混音、响度和 M&E；字幕/图文默认后期并检查安全区与可读性。

## 4. 分层 QC

- 结构层：文件、路径、标签、版本、operation、时码和合同字段。
- 语义层：故事因果、素材权威、人物/产品身份、空间、动作、末态和声音归属。
- 播放层：逐帧漂移、手脸、接触、口型、物理、剪辑点、声画同步和字幕。
- 交付层：分辨率、画幅、帧率、编解码、颜色、声道、响度、文件名和可播放性。
- 业务层：品牌、声明、平台审核、版权、目标人群和投放上下文。

## 5. 双方差异的统一裁决

- 原 Skill 偏提示词与 operation 完整性，v6.7 补专业后期和交付；统一后默认输出仍保持精简，但商业交付必须贯穿阶段与责任。
- prompt lint 或合同覆盖率通过只表示“结构可提交”；不能替代真实生成与业务验收。
- 当前平台 UI、参数、价格和能力必须现场核验；文档版本只提供路由，不提供永久保证。
- 修改现有视频优先最小差异与保留项，不能因“优化”破坏已接受镜头。

## 6. 交付验收

- 当前证据支持的是哪个阶段，是否越级宣称完成？
- operation 的输入、可变项、保留项和失败线是否完整？
- 生成、剪辑、调色、声音、字幕各自职责是否分清？
- 是否验证用户能看到/听到的主路径，而非只检查文件？
- 商业使用是否另行完成权利、平台和投放审查？
