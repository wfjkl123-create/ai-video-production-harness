# 机位物理化与首帧调度

本文件把“高角度、斜侧、荷兰角、越肩、窥视”等抽象词解成相机在世界中的真实位置，并建立可继承的首帧空间关系。

## 1. 先画世界地图

复杂镜头至少锁定：

- 人物/产品的绝对数量和身份；
- 每个主体的身体朝向与视线目标，二者分开记录；
- 画面左/右、前/中/后景及深度顺序；
- 动作轴、对话轴、接触关系、运动方向和动作终点；
- 相机可站区域、墙/车体/家具等不可穿越边界；
- 关键前景锚、遮挡物、入口、出口和揭示对象。

屏幕坐标不能代替物理关系。先写“人物面向门、视线回到同伴、相机在动作轴右侧”，再把结果编译成画面左/右；否则人物转身或切镜后容易越轴。

## 2. 机位五元组

强角度或空间高风险镜头必须解出：

1. `height`：相机相对主体眼线/腰线/地面的高度；
2. `side`：相机位于动作轴或主体的左/右/正前/正后；
3. `distance_or_clearance`：与主体距离及可用净空；
4. `aimPoint`：瞄准眼睛、胸口、手/产品、地面接触点或远端出口；
5. `roll`：只有画面地平线需要倾斜时写滚转方向；俯拍/仰拍不等于滚转。

正文不一定逐字段输出，但必须把可见结果写清。例如不要只写“高角度荷兰角”，而要说明相机高于人物眼线、位于动作轴哪侧、向哪个可见目标俯拍、画面哪一侧下沉，以及前景用什么证明倾斜。

## 3. 朝向、视线与相机侧别分离

- 身体朝向回答“胸口和脚尖朝哪”；视线回答“眼睛正在看谁/哪里”。
- “从人物左侧拍”回答相机位置，不等于人物看向画面左。
- 对话镜头先锁 180° 轴和双方视线方向；跨轴必须有明确越轴动作、过渡机位或切换动机。
- 接触镜头同时锁双方接触部位、受力方向和结束关系，不能只锁画面左右。

## 4. 首帧不是统一模板

默认规则：当前节拍的关键主体、动作起点和空间参照在首个有效画面中可读，避免无意义的空镜等待。

以下是受保护例外：

- `intentional_empty`：空镜本身建立期待、孤独、监控或危险；
- `entrance`：主体从明确入口进入，空画面负责建立入口和方向；
- `reveal`：主体/产品被前景、门、布、转身或光线有意延迟揭示；
- `pov_recovery`：眨眼、白闪、黑场、曝光恢复或遮挡解除本身是主观事件；
- `device_setup`：前景/背景参照必须先建立，随后装置才可被读懂。

命中例外时，不得自动改成“所有主体首帧已经完整可见”。必须写清 `dramaticTask`、`revealTrigger`、`firstVisiblePosition` 和 `postRevealState`；缺一项即不是可执行的有意例外，不能用模式名掩盖无意义空等。

## 5. 第一帧到动作终点

首帧合同至少回答：

```text
谁已在场 / 谁尚未出现
主体在哪里、朝向哪里、看向哪里
产品/道具在哪里、由谁接触
相机在哪里、当前画框和前景锚是什么
动作已经开始、尚未开始，还是等待明确触发
揭示发生后结束在什么位置/朝向/接触状态
```

不要把首帧写成静态证件照。除有意停顿外，人物应在做已有任务或保持一个物理状态；动作由画内触发继续。

## 6. 强角度验收

- 机位五元组是否足以在真实空间放置相机？
- 身体朝向、视线目标、相机侧别是否没有偷换？
- 俯仰和滚转是否分开，倾斜是否有地平线/门框/桌边等参照？
- 前景是否服务深度、揭示或装置，而不是随机遮脸？
- 首帧默认规则是否尊重有意空镜、入场和揭示？
- 结束状态是否能交给下一镜，而不是切镜后人物复位？
