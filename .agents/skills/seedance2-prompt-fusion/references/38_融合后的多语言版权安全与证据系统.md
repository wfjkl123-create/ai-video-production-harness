# 融合后的多语言、版权安全与证据系统

本文件融合原 Skill 的中文主体/英文锚点、2.5 双源证据与版本边界，和 v6.7 multilingual、vocab、examples、copyright、filter、source registry 与 research 方法。

## 1. 多语言以语义保真为首要目标

访谈、brief 和成稿使用用户语言；平台原生标签逐字保留。中文任务以中文因果、动作、空间和末态为主体，英文只保留必要摄影、剪辑、媒介或平台锚点。翻译时保持角色归属、动作方向、否定范围、时码和素材标签，不追求逐词对齐。

词库提供表达候选，不是标签拼盘。专业术语只有在目标语言用户和平台均能理解、且比自然语言更准确时保留；否则翻成观众可见结果。多语言对白需母语者或可靠语音审校，尤其检查时长、口型、敬语、双关和文化含义。

## 2. 创意阶段与真实使用阶段分层

创意构思不因尚未要求投放而提前压缩题材；当用户明确要生成真实人物、品牌交付、发布、上架或投放时，再执行权利、安全与平台门。不得用安全审查替用户改写创意目标，也不得把技术可生成误写成有权使用。

真实人物、声音、商标、角色、影片、音乐、字体和用户素材分别记录来源、授权范围、地区、期限与允许变换。避免通过命名在世艺术家、导演或受保护工作室来替代可执行风格描述。

## 3. 证据分级与版本隔离

- 当前官方页面/当前 UI/当前运行结果：可支持当次能力判断。
- 官方文档或 Word 双源快照：支持版本化合同，但可能随更新失效。
- 用户案例、上游 example、社区观察：支持写法或假设，不证明普遍能力。
- 内部启发式：用于保守决策，必须明确不是官方上限。

2.0 与 2.5 的时长、素材上限、模型名、端点、参数和 UI 不交叉继承。v6.7 的导演方法可以迁移，产品数字必须由对应版本当前证据覆盖。

## 4. 过滤与约束的正确位置

先写正向可见目标与允许内容，再在末尾封最重要的文字、身份、结构、暴力/裸露或平台风险。过滤词表用于发现风险，不作为创作词库，也不能通过反复点名把污染元素引入画面。

## 5. 双方差异的统一裁决

- 原 Skill 的“中文为主、英文锚点白名单”是默认成稿策略；v6.7 六语言词库按需提供本地表达，但不替代语义与母语审校。
- 原 2.5 在线/Word 双源与 v6.7 source registry 统一为来源、日期、版本、验证状态和能力边界记录。
- 示例只证明一种组织方法；未运行生成、未看视频、未核授权时，不得写“已验证可用/可投放”。
- 权利、安全、平台规则会变化，实际发布或投放前必须使用当前一手证据重新核验。

## 6. 证据与安全验收

- 标签、角色、方向、时码和否定范围在翻译后是否保持？
- 能力结论来自当前官方/界面，还是只来自案例和旧文档？
- 是否明确区分启发式、观察、官方合同和实际运行结果？
- 真实使用所需权利是否有来源与范围，而非默认推定？
- 创意、生成、发布和投放的审查门是否分层报告？
