# 融合后的去 AI 味、失败诊断与返工系统

本文件融合原 ref 04/09/21/26 的防污染、UGC 非完美、抽卡修正和细节引擎，与 v6.7 anti-slop、failure atlas、troubleshooting、retake workflow 和 evaluation rubric。

## 1. 去 AI 味先去空洞因果

AI 感常来自：人物无任务、动作无触发、镜头无动机、光无来源、材质无反馈、全员同步、效果不进入环境、风格标签代替可见事实。修复优先补因果与选择，不是随机添加眨眼、手持抖动、胶片颗粒、慢动作和漂浮粒子。

抽象词统一换成证据：尴尬变成话说一半后继续整理桌面；高级变成稳定轮廓、受控反射和干净终态；震撼变成比例、遮挡、环境后果和延迟反应。

## 2. 先分类失败，不立刻重写全部

按证据归类：身份/产品漂移、素材污染、动作瞬移、物理失重、空间/轴线错误、事件超载、表演僵硬、摄影/光无动机、声音归属或同步错误、连续性错位、文字/合规/交付问题。指出最早出现的失败帧与最可能控制变量，保留其余已成功部分。

摄影失败再细分四类：镜头任务与可读尺度不匹配、机位在真实空间中无净空、两个以上强镜头装置争夺同一节拍、首帧默认规则覆盖了用户有意的空镜/入场/揭示。命中时读取 ref 40 与对应的 refs 41–43，不用增加“电影感”或更多摄影术语掩盖矛盾。

## 3. 最低成本返工阶梯

1. 局部改词或删除污染词；2. 收敛一个动作/运镜/角色；3. 强化正向身份、位置、接触和末态；4. 调整素材 owner 或 transfer/ignore；5. 拆 clip 或改变 control level；6. 从 accepted frame/canonical 资产重锚；7. 必要时才重做上游资产或整段。

每次 retake 只改变一个主要变量，记录假设、改动、保持项和结果。设定尝试预算；连续失败说明合同或素材有系统问题，不继续盲抽。

“一个主要变量”不等于假装失败只有单一原因。记录时保留：主要根因、共同作用因素、支持证据、反证、未知和下一项最小验证。真人感 FAIL 至少分别检查身份/故事状态资产、景别可读性、动作因果、表演时序、场景几何、声音策略、平台控制和生成随机性。同一根因未改变控制路线前，不得只换 seed 或同义词再次付费。

## 4. 介质非完美必须有拍摄者

UGC、直播、DV、监控或幕后素材先确定设备、操作者和拍摄原因，再允许一个符合因果的偏差：捕捉晚半拍、短暂失焦、构图修正、曝光追赶或风噪。每镜一个足够；同一套缺陷反复出现会成为新的模板味。

## 5. 双方差异的统一裁决

- 原 Skill 的“不要点名污染元素”与 v6.7 负面约束合并：优先正向结果；只有高概率、可识别且无法靠正向锁定封住的失败才在末尾简短排除。
- 原抽卡修正升级为受控 retake：不以“多抽几次”代替诊断，必须比较实际 take。
- v6.7 failure atlas 是诊断分类，不是把所有失败项塞进每条提示词。
- 结构 lint 只能发现形式错误；人物真实感、故事语义、产品准确、投放可用仍需播放级人工验收。

## 6. 返工验收

- 最早失败点和失败类别是否有真实画面证据？
- 本次只改变了一个主要变量吗，成功部分是否被保持？
- 去 AI 方案是否来自任务因果，而不是随机装饰？
- 失败是否已触发拆段、重分权威或 canonical 重锚，而非继续盲抽？
- 是否先修正镜头任务、可读尺度、机位净空或主装置冲突，再考虑换风格和堆参数？
- 是否分别记录提示词 PASS、生成观察、业务验收和投放状态？
