# 融合后的素材权威角色身份与多模态系统

本文件融合原 ref 03/05/07 与 2.5 多模态手册的参考源分工、资产首帧和身份锁，与 v6.7 reference workflow、reference transfer contract、characters、surface profiles、I2V/R2V 和 first-last-frame。

## 1. 每个受控维度只有一个权威来源

先列维度：人物身份、产品结构、服装、场景设计、构图、姿态、运动、镜头、声音、首态、末态。每一维指定唯一 owner；其他素材只可提供明确辅助信息。来源冲突时不平均融合，按任务目标重新裁定 owner。

每个素材使用五字段：精确标签/稳定 ID、素材类型、负责维度、允许迁移、禁止迁移。例如视频只借动作节奏与镜头轨迹，不借人物、服装、背景和色彩；人物板只锁身份，不自动锁声音、姿态或构图。

## 2. 标签与 Harness ID 同时保真

用户或界面给出的 `@Image1`、`@Video1`、`@Audio1`、`@图片1` 等逐字保留，不翻译、不重编号。Harness 内部继续使用 `@素材[exact-id]`；只有最终编译器按实际媒体顺序机械映射，写作者不得手工猜号。

## 3. canonical 身份与瞬时状态分离

- canonical 资产负责脸、体态、产品、服装、世界和长期设计。
- 接受视频/尾帧负责当前姿态、站位、视线、道具状态、动作阶段和摄影阶段。
- 动作参考负责获授权的运动/镜头维度。
- 漂移成片不能因为“观察优先”自动升级为新身份事实；必要时从 canonical 资产重锚定。

## 4. 多角色与多素材隔离

每个角色使用稳定标签，分别声明身份、位置、动作、视线、台词和末态。多主体参考必须写选择器，防止把 A 的脸、B 的衣服和 C 的动作混成一人。背景、姿态和构图默认不从身份图迁移；只有明确授权才复用。

首帧用于焊接开镜构图与状态，尾帧用于边界或延续，不承担完整剧情因果。人物身份资产按已锁定 Shot 的可见覆盖反推：需要什么角度才生成什么角度；固定四视图只是四个身份维度都实际出镜时的条件组合。角色身份包和产品板先保证单个 canonical 形象一致，再用于复杂场景；上游资产未锁定时，不用下游提示词补救身份混乱。长期行为身份、剧情状态与声音身份分别由 Master Profile、story state 和 voice identity 承担，详见 ref 44。

## 5. 双方差异的统一裁决

- 原 Skill 的“@参考源分工”升级为逐维权威矩阵；v6.7 的 transfer/ignore 条款必须落到每个素材，不只写“参考”。
- 原首尾帧连续性与 v6.7 observed-state 结合：尾帧控制瞬时态，canonical 控制身份，两者并行而非互相覆盖。
- 2.0/2.5 的输入数量、格式、上传方式和 UI 只按当前官方或界面证据；多模态原则可迁移，平台数字不可跨版本套用。
- 权利或授权不明的真实人物、商标、声音和受保护内容，不能因技术上可引用就视为可用。

## 6. 素材验收

- 每个受控维度是否只有一个 owner？
- 每份素材是否同时写了允许与禁止迁移？
- 标签是否逐字保留，Harness ID 是否未被手工重排？
- canonical 身份与 accepted footage 的瞬时状态是否分开？
- 多角色动作、声音、站位和末态是否逐一归属？
