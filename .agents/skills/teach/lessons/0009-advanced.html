Claude How-To 课程 · 模块 9

高级特性：让 Claude 更谨慎、更深思

第 9 课，共 10 模块 · 预计 15 分钟

这节课介绍三个"增强剂"：不改变 Claude 能做什么，但让它做得更好、更安全、更彻底。

📋 Plan Mode（规划模式）安全

默认情况下，Claude 会边想边做——你说"重构这个模块"，它可能直接就开始改文件了。 Plan Mode 改变了这个顺序：先出计划，确认后再动手。

你发出任务
→
Claude 列出计划
（不做任何修改）
→
你审查计划
确认 / 修改
→
Claude 按计划执行

如何启用：

claude --plan          ← 启动时开启规划模式
/plan                  ← 对话中切换（如果已配置）

或者在对话里直接说：

在做任何修改之前，先给我一个详细的执行计划

适合用的时候

  • 重构大量文件
  • 数据库迁移
  • 第一次让 Claude 接触陌生项目
  • 任何"做错很难撤销"的操作

不必要的时候

  • 简单问答
  • 生成新文件（不影响现有内容）
  • 你已经很熟悉 Claude 会做什么

🧠 Extended Thinking（扩展思考）质量

普通模式下 Claude 会快速回答。Extended Thinking 让它在回答之前慢下来，深度推理—— 把思考过程完整展开，像解数学题一样一步一步推导。

你会在回答前看到一个"思考过程"区块，展示 Claude 如何分析问题、权衡选项、得出结论。

如何启用：

claude --thinking               ← 命令行开启扩展思考
claude --thinking-budget 8000  ← 指定最大思考 token 数

或者在对话里说：

请仔细思考这个问题，把你的推理过程展示给我

思考深度越高，消耗的 token 越多，但答案质量往往也更好：

普通模式
快 ⚡
扩展思考
深 🧠

适合用的时候

  • 复杂架构设计决策
  • 调试难以复现的 bug
  • 算法选型和性能分析
  • 需要权衡多种方案

不必要的时候

  • 简单问答和翻译
  • 生成模板代码
  • 日常文件读写操作

⏳ Background Tasks（后台任务）效率

有些任务耗时很长——跑完整的测试套件、处理大量文件、等待构建完成。 你不可能一直盯着屏幕。Background Tasks 让 Claude 在后台独立执行， 完成后通知你。

如何使用：

claude "帮我跑所有测试并生成报告" --background

或者与 GitHub Actions 集成——在 PR 里 @ Claude， 它会在 CI 环境里后台执行任务，完成后在 PR 里回复结果。

三个特性组合使用
Plan Mode（先规划） + Extended Thinking（深思熟虑） + Background Tasks（后台执行）= 对复杂任务的完整工作流：想清楚 → 确认 → 放心去做。
