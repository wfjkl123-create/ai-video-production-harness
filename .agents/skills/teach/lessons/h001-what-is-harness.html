什么是 Harness

共 7 课 · 预计 12 分钟

你现在面对的问题

你已经学会了 Claude Code 的所有组件。但现在，每次打开一个新项目，你还是得：

典型的一天
"帮我用中文回复"
"不要加注释"
"改完代码记得跑测试"
"不要动 config.json"
"用 TypeScript，不要用 any"
……每次都要重新说一遍。

Harness（驾驭系统）解决的就是这个问题： 把这些规则编码进环境本身，让 Claude 每次都自动遵守， 不需要你重复说明。

一句话定义
Harness = 让 Claude 每次都自动按你的规则工作 的持久化配置层。
来源：Harness Engineering Guide

一个类比

想象你有一个新员工（Claude）。每天上班你都要跟他说一遍工作守则。 Harness 就是把工作守则印在工牌上，贴在工位旁，写进入职手册—— 他一坐下来，规则就自动生效。

🗣️
没有 Harness
每次对话重新解释规则，Claude 在不同会话里表现不一致
→
🏗️
有 Harness
规则编码在环境里，Claude 每次自动遵守，行为始终一致

Harness 的五大支柱

一个完整的 Harness 由五种组件构成——你在 claude-howto 课程里已经学过它们每一个， 现在我们要把它们工程化地组合起来：

支柱 1
📄 CLAUDE.md
项目文档，每次会话自动加载。写项目背景、规范、禁止事项。
CLAUDE.md / ~/.claude/CLAUDE.md
支柱 2
⚙️ Settings & Permissions
精确控制 Claude 被允许做什么、禁止做什么。
.claude/settings.json
支柱 3
🪝 Hooks
自动化脚本，在 Claude 执行特定动作时触发，强制执行工作流。
settings.json → hooks
支柱 4
🧩 Skills
按需加载的专属指令集，处理特定场景时自动激活。
~/.claude/skills/
支柱 5
⚡ Custom Commands
把高频重复任务变成一键斜杠命令，减少摩擦。
~/.claude/commands/ / .claude/commands/

有 Harness 和没有 Harness 的差别

❌ 没有 Harness

  • 每次新对话重新交代背景
  • Claude 偶尔忘记你的偏好
  • 改完代码要手动提醒跑测试
  • 不同项目里 Claude 行为不一致
  • 重要文件可能被意外修改

✅ 有 Harness

  • 打开项目，Claude 自动知道上下文
  • 规则写进环境，永远不会"忘"
  • PostToolUse Hook 自动跑测试
  • 每个项目有自己的定制化行为
  • PreToolUse Hook 保护重要文件

本课程的目标

接下来的 6 课，我们会逐一深入每个支柱，然后在最后一课把它们整合成 你自己的第一个完整 Harness——一个真实可用的个人 Claude Code 配置系统。

学完之后，你的 ~/.claude/ 目录会变成一个有组织的工程：

~/.claude/
├── CLAUDE.md          ← 你的全局规则
├── settings.json      ← 权限 + Hooks 配置
├── commands/          ← 你的专属命令
├── skills/            ← 你的技能库
└── memory/            ← Claude 的长期记忆
