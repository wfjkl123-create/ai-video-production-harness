CLAUDE.md 工程化：写好 Claude 的"入职手册"

第 2 课，共 7 课 · 预计 15 分钟

CLAUDE.md 是 Harness 的大脑

你在 claude-howto 课程里学过 CLAUDE.md 的基本概念——它是 Claude 每次会话自动加载的文件。 但"随手写几行"和"工程化设计"之间，有巨大的差距。

一个写得好的 CLAUDE.md，能让 Claude 在第一条消息之前就已经理解： 这是什么项目、应该怎么工作、什么绝对不能碰。

来自 Harness Engineering Guide
"Be specific: 'Use TypeScript strict mode with explicit return types' beats generic statements."
具体胜过模糊。规则越具体，Claude 越能准确遵守。

一个工程化 CLAUDE.md 的解剖

根据最佳实践，一个完整的项目 CLAUDE.md 应包含五个区块：

📋 项目概览
这是什么项目、技术栈、部署方式。让 Claude 立刻定位上下文。
⚡ 关键命令
dev / test / lint / build 的具体命令。Claude 知道用哪条命令做什么事。
📐 编码规范
语言风格、命名规则、禁用的写法。这是最常被忽视但最重要的部分。
🗂️ 架构说明
目录结构和文件组织方式。让 Claude 知道在哪里找什么、改什么放哪里。
🚫 重要规则
绝对不能做的事。这是 Harness 的护栏，必须写得清晰明确。

具体 vs 模糊：最关键的原则

CLAUDE.md 里每一条规则，都应该具体到 Claude 不需要"理解"就能执行：

❌ 模糊（无效）

写好代码。
注意代码质量。
遵守团队规范。

✅ 具体（有效）

使用 TypeScript strict 模式。
函数必须有明确的返回类型。
禁止使用 any，用 unknown 替代。

❌ 无理由（容易被绕过）

不要修改 config.json。

✅ 有理由（约束力更强）

不要修改 config.json——
它由 CI/CD 系统自动生成，
手动修改会在下次部署时被覆盖。

写规则时，加上"为什么"。Claude 理解了原因，在边界情况下也能做出正确判断， 而不是机械执行。

全局 vs 项目的分工

CLAUDE.md 有层级，每层负责不同的事：

🌍 全局
~/.claude/CLAUDE.md
所有项目都适用的个人偏好
↓ 叠加
📁 项目根
项目根/CLAUDE.md
这个项目的规则和上下文
↓ 叠加
📂 子目录
src/CLAUDE.md
某个模块特有的规则

分工建议：

# ~/.claude/CLAUDE.md（全局）写什么
- 语言偏好（用中文回复）
- 通用编码风格（不加注释，除非 WHY 非常不明显）
- 个人习惯（不用 emoji，回答要简洁）

# 项目/CLAUDE.md（项目级）写什么
- 这个项目是什么
- 运行 / 测试命令
- 特定于这个项目的规范
- 禁止修改的文件和原因

常见反模式（避免这些错误）

反模式 1：把 CLAUDE.md 当知识库

超过 500 行的 CLAUDE.md 是一个信号——你在往里塞太多东西了。 详细的 API 文档、大段的业务说明，应该放进 Skills 或单独的文档，用链接引用，而不是直接粘贴进来。

❌ 知识库式（臃肿）

## API 文档
POST /api/users
参数：name, email, role...
（200 行 API 说明）

✅ 指针式（精简）

## API
详见 ./docs/api.md
核心端点：POST /api/users,
GET /api/users/:id

反模式 2：从不更新

CLAUDE.md 写完就放着不管是最常见的错误。项目在演化，CLAUDE.md 也要跟着更新。 建议每次重要重构后，把 CLAUDE.md 更新列入 checklist。

动手：写你的第一个全局 CLAUDE.md

在 Claude Code 里输入 /memory（不带参数），打开你的全局 CLAUDE.md， 参照下面这个模板填写你自己的偏好：

# 我的全局偏好

## 语言
- 始终用中文回复

## 回答风格
- 回答简洁，不要废话
- 不要在回答末尾加总结性段落
- 代码里不加注释，除非逻辑非常不明显

## 代码习惯
- 变量名用英文
- 优先考虑可读性，不要过度优化
- 改动最小化：不要重构超出任务范围的代码

填完保存，下次打开 Claude Code 就会自动生效。

小测验

测验 1 / 3
CLAUDE.md 里有一条规则"不要修改 config.json"，但 Claude 在某个边界情况下不确定是否应该例外。哪种写法能让它做出更好的判断？
测验 2 / 3
你的项目有一份 200 行的 API 文档，应该怎么处理它和 CLAUDE.md 的关系？
测验 3 / 3
语言偏好（如"用中文回复"）应该写在哪个 CLAUDE.md 里？
