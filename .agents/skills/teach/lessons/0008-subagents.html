Subagents：让 Claude 分身工作

第 8 课，共 10 模块 · 预计 15 分钟

一个人做不完，就派人去做

你让 Claude 做一个复杂任务："帮我审查整个代码库，找出安全漏洞、性能问题和代码规范问题。"

如果 Claude 一个人从头到尾做，又慢又容易混乱。更好的方式是： 主 Claude 当"项目经理"，派出多个专职"小 Claude"并行处理。

🧠 主 Claude（编排者）
🔒 安全检查
Subagent
⚡ 性能分析
Subagent
📐 规范检查
Subagent

三个 Subagent 同时工作，最后把结果汇总给你——比串行执行快得多。

为什么要用 Subagents

场景 不用 Subagent 用 Subagent
审查 100 个文件 一个个排队，耗时长 10 个 Subagent 各管 10 个，并行处理
专业任务 主 Claude 什么都管，容易分心 每个 Subagent 只专注自己的领域
超长任务 对话太长，Claude 开始"忘事" 每个 Subagent 有独立的干净上下文
关键优势：独立上下文
每个 Subagent 都有自己全新的、干净的对话上下文，不受主对话的干扰。 这避免了"对话越来越长，Claude 越来越混乱"的问题。

Subagent 怎么定义

Subagent 定义在 agents/ 目录下，每个文件是一个专职代理： 

~/.claude/agents/                ← 全局 Subagent
.claude/agents/                  ← 项目级 Subagent
  ├── security-reviewer.md
  ├── performance-analyzer.md
  └── test-writer.md

一个 Subagent 定义文件长这样：

---
name: security-reviewer
description: 专门负责审查代码安全漏洞的代理
tools: Read, Grep
---

# 安全审查专家

你是一个专注于代码安全的审查员。
你的任务是找出以下问题：
- SQL 注入漏洞
- XSS 跨站脚本攻击
- 不安全的密钥硬编码
- 权限控制缺失

审查时只关注安全问题，不评论代码风格或性能。
输出结构化的漏洞报告，标注严重级别。

注意 tools 字段——你可以限制 Subagent 能用哪些工具， 让它保持专注，也更安全。

主 Claude 如何派遣 Subagent

你不需要手动触发 Subagent——当你给主 Claude 一个复杂任务，它会自动判断是否需要派遣 Subagent， 以及派遣哪些。你也可以在提示词里明确要求： 

请用多个代理并行审查 src/ 目录：
- 一个负责安全漏洞
- 一个负责性能问题
- 一个负责测试覆盖率
最后汇总报告给我。

Claude 会自动协调，你等着收汇总结果就好。

一个完整的并行任务例子

你说："帮我准备明天的技术分享，需要 PPT 大纲、演示代码和 README。"

📑 大纲 Agent
生成 PPT 结构和每页要点
💻 代码 Agent
写可运行的演示代码
📄 文档 Agent
写 README 和使用说明

三个 Agent 同时工作，几分钟内交付全套材料，而不是一个接一个排队等。
