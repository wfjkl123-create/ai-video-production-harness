Checkpoints：后悔药

第 3 课，共 10 模块 · 预计 10 分钟

当 Claude 走错了方向

你让 Claude 帮你重构一个函数。它改了十几个文件，但越改越偏——你发现它根本误解了你的意思。 怎么办？逐条撤销？重新开始？

Checkpoints（检查点）就是解决这个问题的。它是对话的"存档点"—— 你可以随时回到某个历史节点，就像游戏里的存档，从那里重新出发。

对话是一棵树，不是一条线

通常我们以为对话是线性的：你问，Claude 答，继续往前。但实际上，Claude Code 允许对话分叉——从任何一个历史节点出发，走出一条全新的分支。 

你: 帮我重构 main.py
  │
Claude: 好的，我来分析...     ← 检查点 A
  │
Claude: 修改了文件 1/5...
  │
Claude: 修改了文件 2/5...
  │
你: 等等，你理解错了！
  │
  ╠══ 回到检查点 A，重新说清楚需求 → 新的分支 ✓
  │
  ╚══ 继续当前错误路径（继续改错） ✗

回到检查点 A 后，你可以重新描述需求，Claude 会从那个节点重新响应——像是"时间倒流"。

如何使用 Checkpoints

方式一：在对话中点击历史消息（桌面 / Web 版）

把鼠标悬停在任意一条你发出的消息上，会出现一个 「Edit」或「Restore」按钮。点击后可以：

  • 编辑那条消息，重新发送（会从那个节点创建新分支）
  • 丢弃这条消息之后的所有内容，重新开始

方式二：在终端版中使用 Esc 键

在 Claude Code 终端里，当 Claude 正在运行时，按 Esc 可以中断当前任务。 Claude 会停下来并询问你下一步。这是最快的"叫停"方式。

实用技巧
在发出重要请求之前，先说清楚。与其事后回退，不如在让 Claude 开始做事之前， 把目标、约束、不能改的地方都交代清楚。检查点是后悔药，但好的提示词才是正确做法。

方式三：手动插入检查点标记

你可以在对话里输入类似"好的，现在我们进入下一阶段"这样的分隔语， 方便你事后找到回退位置。虽然不是技术上的检查点，但在实际使用中非常有用。

什么时候该用 Checkpoints

你说："帮我给这段代码写测试，只测 login 函数" 好时机存档
Claude 开始写测试……
Claude 顺手也改了 login 函数本身（你没让它改！）
→ 回到"好时机存档"那条消息，重新说："只写测试，不要修改 login 函数本身"

使用场景总结：

  • Claude 误解了你的意图，已经改了很多东西
  • 你想对同一个问题尝试不同的解法，做对比
  • 你不小心说了模糊的话，想重新表述
  • Claude 的回答不满意，想让它"重新来"
