Custom Commands：把高频任务变成一键触发

第 6 课，共 7 课 · 预计 12 分钟

你的 commands/ 目录目前是空的

⚠ ~/.claude/commands/ 还没有任何命令 这节课结束后，你将为自己的 Harness 创建第一批专属命令。

Custom Commands 是 Harness 五大支柱里最轻量的一个—— 一个 .md 文件就是一个命令。但别小看它： 一个设计精准的命令，能把一个复杂的重复任务压缩成两三个字。

命令 vs Skill：如何选择

⚡ Custom Command（命令）

  • 单个 .md 文件，极简
  • 用户主动输入 /name 触发
  • 适合快速、聚焦的单次任务
  • 适合需要传参数的场景
  • 团队共享（提交到 Git）

🧩 Skill（技能）

  • 完整目录结构
  • 可自动触发（关键词匹配）
  • 适合多步骤、有状态的工作流
  • 可以携带参考文档和脚本
  • 通常是个人工具库

简单判断：需要自动触发或多个文件支撑 → Skill； 用户手动触发、一个文件搞定 → Command。

$ARGUMENTS：让命令接收参数

命令文件里写 $ARGUMENTS，用户输入 /命令名 参数内容 时， 参数会自动替换进去：

/test user-auth
→
命令内容：
"为 user-auth 模块运行测试， 分析失败原因，自动修复并重新验证。"

命令文件（test.md）内容：

为 $ARGUMENTS 模块运行测试。
如果有失败：
1. 找出失败原因
2. 修复代码（不修改测试）
3. 重新运行验证通过

$ARGUMENTS 是命令文件里最重要的功能—— 它把静态指令变成了动态工具。

命令的存放位置

位置 路径 调用方式 适合放
全局 ~/.claude/commands/cmd.md /cmd 个人通用命令
项目 .claude/commands/cmd.md /cmd 团队共享的项目命令
插件命名空间 插件内的 commands/ /插件名:cmd 插件提供的命令

五个真实可用的命令配方

🔍 代码审查 ~/.claude/commands/review.md 
审查以下代码的 git diff，检查这五个维度：

1. **正确性**：逻辑错误、边界情况、空指针
2. **安全性**：注入风险、硬编码密钥、权限问题
3. **性能**：无谓循环、重复计算、N+1 查询
4. **类型安全**：any 滥用、类型断言是否合理
5. **测试覆盖**：新功能有没有对应的测试

```bash
git diff HEAD~1
```

每个问题格式：[严重级别: 高/中/低] 文件:行号 — 问题 → 建议

按严重级别从高到低排列。
不需要参数，直接 /review 就审查最新的 commit diff。
🧪 运行指定模块测试 ~/.claude/commands/test.md 
为 $ARGUMENTS 运行测试。

步骤：
1. 找到和 $ARGUMENTS 相关的测试文件
2. 运行测试：`npm test -- $ARGUMENTS`
3. 如果有失败，分析每条错误信息
4. 修复源码中的 bug（不修改测试本身）
5. 重新运行，直到全部通过

完成后告诉我：修复了几个问题，改了哪些文件。
用法：/test login —— 运行 login 相关的所有测试。
📝 生成提交信息 ~/.claude/commands/commit.md 
根据当前 staged 的变更，生成一条 git commit 信息。

```bash
git diff --staged
```

格式要求：
- 第一行：50 字以内的中文摘要，动词开头（添加/修复/重构/更新）
- 空一行
- 正文：说明为什么做这个改动（不只是做了什么）
- 不超过 3 条要点

只输出 commit 信息本身，不要解释。
/commit 自动读取 staged 变更并生成规范的提交信息。
📖 解释代码 ~/.claude/commands/explain.md 
解释 $ARGUMENTS 这段代码的作用。

要求：
- 用中文，面向非专业读者
- 先说这段代码总体做什么（一句话）
- 再逐步骤解释关键逻辑
- 指出任何值得注意的设计决策或潜在问题
- 不要重复代码本身
用法：/explain @src/auth.ts —— 解释指定文件。
🌿 创建功能分支 .claude/commands/branch.md 
创建一个新的功能分支并切换到它。

分支名称：feature/$ARGUMENTS

步骤：
1. 确认当前在 main/master 分支且工作区干净
2. `git checkout -b feature/$ARGUMENTS`
3. 确认切换成功
4. 提示下一步：开始开发并用 /commit 生成提交信息
项目级命令。用法：/branch user-profile-page —— 创建 feature/user-profile-page 分支。

动手：创建你的第一个命令

现在就创建 /commit 命令（最实用的起点）：
