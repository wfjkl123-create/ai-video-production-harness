Hooks：给 Claude 装上自动反应

第 6 课，共 10 模块 · 预计 15 分钟

Claude 做事，Hook 在旁边守着

想象你雇了一个助手（Claude），但你希望它每次改完代码都自动跑一遍测试， 每次写文件都自动格式化，遇到危险命令就先停下来问你。 你不可能每次都盯着它手动做这些事——这就是 Hooks（钩子） 存在的意义。

Hook 是挂在 Claude 动作上的自动脚本： Claude 一做某件事，对应的 Hook 脚本就自动跑起来。

Hook 的触发时机

Claude Code 提供四个可以挂钩子的事件节点：

PreToolUse

Claude 调用某个工具之前触发。可以用来检查、拦截危险操作。

PostToolUse

Claude 调用某个工具之后触发。可以用来自动运行测试、格式化代码。

Notification

Claude 需要通知用户时触发。可以用来发桌面通知、发钉钉消息。

Stop

Claude 完成一轮任务时触发。可以用来生成报告、记录日志。

以 PostToolUse 为例，完整的执行流程是：

你发出指令
→
Claude 修改文件
→
PostToolUse Hook 触发
→
自动跑 npm test
→
结果反馈给 Claude

Hook 配置在哪里

Hooks 不是放在某个目录下的文件，而是配置在 settings.json 里： 

~/.claude/settings.json      ← 全局 Hook（所有项目）
.claude/settings.json        ← 项目 Hook（只在此项目）

配置格式如下：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "npm test"
          }
        ]
      }
    ]
  }
}

这段配置的意思：每当 Claude 使用 Write 工具（写文件）之后， 自动执行 npm test。

matcher 是过滤器
matcher 决定哪些工具操作会触发 Hook。常用值有： "Write"（写文件）、"Bash"（执行命令）、"Edit"（编辑文件）。 留空则对所有工具都触发。

Hook 脚本的返回值

Hook 脚本的退出码（exit code）决定了 Claude 接下来怎么做——这是 Hooks 最关键的机制：

退出码 含义 Claude 的反应
0 成功 继续执行。如果脚本有输出，Claude 会读取并参考
2 阻断 停止当前操作，把脚本的输出作为错误原因告知 Claude
其他 非致命错误 记录错误但继续执行

利用退出码 2，你可以写一个"守门人" Hook：

#!/bin/bash
# PreToolUse Hook：阻止 Claude 删除重要文件

TOOL_INPUT=$(cat)  # 读取 Claude 想执行的操作

if echo "$TOOL_INPUT" | grep -q "rm -rf"; then
  echo "⚠️ 禁止执行 rm -rf 命令，请人工确认"
  exit 2            # 阻断操作
fi

exit 0              # 放行

三个实用 Hook 场景

1. 代码写完自动格式化

"PostToolUse": [{ "matcher": "Write", "hooks": [
  { "type": "command", "command": "prettier --write ." }
]}]

2. 任务完成时发桌面通知

"Stop": [{ "hooks": [
  { "type": "command", "command": "notify-send 'Claude 完成了'" }
]}]

3. 阻止写入 .env 文件（防止泄露密钥）

#!/bin/bash
# PreToolUse Hook
if echo "$CLAUDE_TOOL_INPUT" | grep -q '".env"'; then
  echo "禁止修改 .env 文件"
  exit 2
fi
