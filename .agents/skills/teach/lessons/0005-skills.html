Skills：你已经在用的强大系统

第 5 课，共 10 模块 · 预计 15 分钟

你已经在用一个 Skill 了

每次你输入 /teach，你触发的不是一个简单的斜杠命令——它是一个 Skill（技能）。 这节课我们就从它入手，彻底搞清楚 Skill 是什么。

看看 /teach 的存放位置：

~/.claude/skills/teach/
├── SKILL.md ← 技能的"大脑"，定义行为
├── MISSION-FORMAT.md ← 参考文档
├── MISSION.md ← 你的学习目标（本课程生成）
├── RESOURCES.md ← 资料库
├── lessons/ ← 课程文件（你正在看的这个）
├── assets/ ← 共享样式表和 JS 组件
└── learning-records/ ← 你的学习进度记录

SKILL.md 是整个技能的核心——它告诉 Claude：当这个 Skill 被触发时，应该做什么。 其余的文件是它运作时依赖的资源。

Skill vs Slash Command：有什么区别？

📌 斜杠命令（Slash Command）

  • 单个 .md 文件
  • 只能由用户输入 /name 触发
  • 适合简单、一次性的任务
  • 没有附属资源

⚡ Skill（技能）

  • 一个完整的目录
  • 可以由 /name 触发，也可以自动触发
  • 适合复杂、有状态的任务
  • 可以包含参考文档、脚本、资产
关键区别：自动触发
Skill 的 SKILL.md 里可以定义触发条件——当对话内容匹配某些模式时，Claude 会自动调用这个 Skill，不需要用户手动输入命令。 比如某个 Skill 可以设置为"当用户说想学某样东西时自动激活"。

SKILL.md 的结构

一个 Skill 的 SKILL.md 通常包含以下几个部分：

# Skill 名称

## 描述
这个 Skill 做什么，什么时候应该被触发。

## 触发条件（Triggers）
- 用户说了什么词、做了什么事时自动激活
- 或者通过 /skill-name 手动触发

## 行为（Behavior）
当 Skill 被触发后，Claude 应该做什么，
遵循什么格式，注意什么规则。

## 参考资料
- [参考文档1](./references/doc1.md)
- [参考文档2](./references/doc2.md)

你现在用的 /teach 的 SKILL.md 有几百行—— 定义了整套教学哲学、课程结构、文件格式规范。 这就是为什么它能做出这么完整的课程体验。

Skills 存放在哪里

和斜杠命令类似，Skills 也有两个层级：

~/.claude/skills/skill-name/    ← 全局 Skill（所有项目可用）
.claude/skills/skill-name/      ← 项目 Skill（只在该项目可用）

目前你的 ~/.claude/skills/ 里有： teach、aihot、hv-analysis、 khazix-writer、neat-freak、storage-analyzer。 每一个都是一个完整的技能目录。

如何创建自己的 Skill

创建一个 Skill 只需要三步：

  1. 在 ~/.claude/skills/ 下创建一个文件夹，名字就是 Skill 名
  2. 在文件夹里创建 SKILL.md，写清楚触发条件和行为
  3. 重启 Claude Code，新 Skill 自动生效

举个例子，创建一个"代码审查"Skill：

~/.claude/skills/code-review/
└── SKILL.md

SKILL.md 内容：

# Code Review Skill

## 触发
当用户说"帮我审查代码"或"/code-review"时触发。

## 行为
1. 阅读用户指定的文件
2. 检查：命名规范、潜在 bug、性能问题、安全漏洞
3. 用中文输出结构化报告，分优先级标注问题
4. 给出具体的修改建议，不只是指出问题
