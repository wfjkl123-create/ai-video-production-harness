第一次使用 firstmate

H8 · 预计 12 分钟 · 目标：知道怎么发任务、怎么验收、什么时候放手

先纠正一个误解

firstmate 不是一个更聪明的单 Agent。它更像一个项目总管：你只和一个主 Agent 对话，它把任务拆给多个执行 Agent，跟进它们，最后把结果交回给你。

你 说清楚目标、边界、验收标准，批准关键动作。
firstmate 拆任务、派执行者、监督进度、汇总结果。
crewmate 在独立工作区里调查、改代码、跑测试、交付报告或 PR。
小白规则

你不要试图管理每个执行 Agent。你只管理 firstmate：给目标、看汇报、决定是否继续。

两种任务：scout 和 ship

你想要什么 该怎么说 结果是什么
先了解、评估、找风险 “先 scout，不要改代码。” 一份报告、复现步骤、风险清单或方案。
修 bug、加功能、改文档 “这是 ship 任务，完成后给我 PR。” 代码变更、测试结果、PR 或本地待合并结果。

刚开始使用时，优先用 scout。它能让模糊问题变清楚，也能降低误改代码的风险。

三条可直接复制的指令

1. 第一次认识项目

看一下我的 GitHub 项目 <项目名>。
先 scout，不要改代码。
告诉我项目结构、启动方式、测试方式、主要风险点。
用小白能看懂的方式汇报。

2. 修一个小问题

在 <项目名> 里修复 <具体问题>。
这是 ship 任务。
要求：不改无关文件，跑相关测试，完成后给我 PR。
不要合并，等我确认。

3. 并行做几件事

同时做三件事：
1. scout 登录流程有没有风险
2. scout dark mode 改造范围
3. ship 修复 README 的启动说明
能并行就并行，最后统一汇总给我。

验收时只看四件事

你不需要读懂所有实现细节。先问 firstmate 四个问题：

改了哪些文件？
跑了哪些测试？
还有什么风险？
需要我批准什么？

如果这四个问题答不清楚，就不要说“merge it”。

在 Codex 里怎么用 afk

如果你的 Codex 没有发现 firstmate 的内置技能，不要执着于 $afk。直接用自然语言：

我离开一会，进入 afk。
期间只在需要我决策时提醒我。

firstmate 的核心不是命令符号，而是它读懂你的意图并按自己的操作规则执行。

快速自检
你不确定一个项目能不能安全改，第一步应该让 firstmate 做什么？

今天的练习

打开 firstmate 后，发这一句：

请先帮我 scout 当前 firstmate 工作区。
不要改文件。
告诉我它是怎么运行的、我应该怎样给它发任务、有哪些新手风险。

如果看不懂报告，直接追问：“用更小白的话解释，并给我三个例子。”
